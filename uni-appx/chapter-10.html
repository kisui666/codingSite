10.1

先看地图：能力都有哪些，放在哪里

15 分钟 · 讲授

官方 API 文档把能力分成了若干大类。你不需要背，但要知道去哪一类里找：

分类里面有什么（节选）典型需求
设备获取系统信息 / 设备信息 / 窗口信息 / APP 基础信息、授权设置、系统设置、是否模拟器、无障碍、电池、剪切板、打电话、联系人、日历、扫码、罗盘、加速度计、陀螺仪、wifi、内存告警、截屏事件、屏幕亮度、键盘、振动、安装 APK、请求系统权限 / 监听权限申请读设备信息、震动反馈、扫码、权限

更重要的是：这些能力从哪来？

来源怎么用什么时候用
① uni 内置 API 直接 uni.xxx() 首选。官方已经封装好跨端差异，绝大多数需求都在这里
② 插件市场的 uts 插件 从插件市场安装到 uni_modules，按插件文档调用 内置没有、但别人封装好了（例如某个原生 SDK 的桥接）
③ 自己写 uts 插件 在 uni_modules 里写 utssdk，用 UTS 调用平台原生 API 内置没有、市场也没有，或需要对接公司内部 SDK（见 10.8）
ⓘ
一个官方提到、但很多人不知道的定位：

uni 的 API 本身就是用 UTS 写的（开源于官方 uni-api 仓库）。 也就是说，当官方 API 缺某个能力时，你完全可以照着官方源码的写法，自己写一个 uts 插件补上—— 这也是"UTS 不是另一门语言，而是打通原生能力的那把钥匙"的真正含义。

10.2

媒体能力：选图、拍照、预览、压缩、上传

25 分钟 · 讲授 + 演练

"换头像""发帖配图"是校园 App 里最高频的设备能力需求。 它的完整链路是：选择（相册/相机）→ 预览 → 压缩 → 上传。

pages/demo/image.uvue —— 选图到上传的完整链路 
<script setup>
  const files = ref<string[]>([])

  /* ---------- ① 选择图片（相册或相机） ---------- */
  const pick = () => {
    uni.chooseImage({
      'count': 3,                                  // 最多几张（默认 9，App 端不限制）
      'sourceType': ['album', 'camera'],           // 相册 + 相机
      'sizeType': ['compressed'],                  // 只要压缩图，省流量
      'albumMode': 'custom',                       // 自定义媒体选择器（默认）
      // 'crop': { 'width': 1, 'height': 1, 'quality': 80 },   // 需要裁剪时打开（设置后 sizeType 失效）
      'success': (res) => {
        // tempFilePaths 是路径数组；tempFiles 里还能拿到 size 等信息
        files.value = res.tempFilePaths
        console.log('拿到 ' + res.tempFiles.length + ' 张，第一张大小：' + res.tempFiles[0].size + ' B')
      },
      'fail': (err) => {
        // 关键：区分"用户取消"和"没有权限"
        if (err.errCode == 1101001) {
          console.log('用户取消了选择')
        } else if (err.errCode == 1101005) {
          uni.showModal({
            'title': '需要相册/相机权限',
            'content': '请在系统设置中允许本应用访问相册与相机',
            'confirmText': '去设置',
            'success': (r) => {
              if (r.confirm) uni.openAppAuthorizeSetting()   // 跳转系统授权管理页
            }
          })
        } else {
          uni.showToast({ 'title': '选择失败（' + err.errCode + '）', 'icon': 'none' })
        }
      }
    })
  }

  /* ---------- ② 预览（点图放大看） ---------- */
  const preview = (index: number) => {
    uni.previewImage({
      'urls': files.value,
      'current': index
    })
  }

  /* ---------- ③ 压缩（上传前减小体积） ---------- */
  const compress = (path: string) => {
    uni.compressImage({
      'src': path,
      'quality': 70,
      'success': (res) => {
        console.log('压缩后：', res.tempFilePath)
      }
    })
  }

  /* ---------- ④ 上传（第 8 章学过 uni.uploadFile） ---------- */
  const upload = (path: string) => {
    uni.uploadFile({
      'url': BASE_URL + '/upload',
      'filePath': path,
      'name': 'file',
      'success': (up) => {
        uni.showToast({ 'title': '上传成功', 'icon': 'none' })
      }
    })
  }
</script>
chooseImage 参数默认值说明
count9最多可选张数；App 端不限制，微信小程序最多 20
sourceType['album','camera']只想相册就传 ['album']；只想拍照传 ['camera']
sizeType['original','compressed']只要压缩图能显著减小上传体积
albumMode'custom'custom 自定义媒体选择器 / system 系统媒体选择器
crop—裁剪参数（width / height 必填，quality 默认 80、resize）；设置后 sizeType 失效——做头像上传很好用
extension / pageOrientation—extension 按扩展名过滤（仅 H5）；pageOrientation 指定屏幕方向
!
失败回调里的错误码值得记住几个：

1101001 用户取消（不要弹错误提示，用户自己取消的）、 1101005 未获取权限（要引导授权）、 1101003 文件不存在、 1101007 裁剪失败、 1101009 压缩失败。 把"用户取消"也当成错误弹一个红 toast，是很常见的体验减分项。

💡
媒体 API 家族一览（按需求找）：

图片：chooseImage / previewImage / compressImage / getImageInfo / saveImageToPhotosAlbum（它不支持网络图片路径，只能存本地文件）； 视频：chooseVideo / getVideoInfo / compressVideo / saveVideoToPhotosAlbum； 图片或视频二合一：chooseMedia（它的返回值只有 tempFiles，没有 tempFilePaths， 从 chooseImage 迁过来时最容易踩）； 其他：chooseFile（选文件）、createInnerAudioContext（音频播放）、getRecorderManager（录音）。

10.3

扫码：校园签到与设备编号识别

15 分钟 · 讲授

扫码在校园场景里非常实用：签到、借还设备、识别教室二维码、扫描图书条码。 官方 API 是 uni.scanCode。

pages/demo/scan.uvue —— 扫码签到 
<script setup>
  const result = ref<string>('')

  const scan = () => {
    uni.scanCode({
      // 只允许相机扫（不允许从相册选图），适合现场签到
      'onlyFromCamera': true,
      // 指定识别类型：二维码 / 条形码 / DataMatrix / PDF417
      'scanType': ['qrCode', 'barCode'],
      'success': (res) => {
        // res.result 是扫码内容，res.scanType 是识别到的码制
        result.value = res.result
        console.log('扫到 ' + res.scanType + '：' + res.result)
      },
      'fail': (err) => {
        // 注意：小程序端扫码不需要申请相机权限；App 端需要摄像头权限
        console.log('扫码失败：', err.errMsg)
      }
    })
  }
</script>
要点官方说明
平台支持不支持 Web；微信 4.41+、支付宝 5.31+、Android 4.71+、iOS 4.71+、鸿蒙 4.61+
参数onlyFromCamera（只允许相机）、scanType（barCode / qrCode / datamatrix / pdf417）
返回值result（扫码内容）、scanType（码制）
权限App 端需要摄像头权限；扫码界面里的相册图标点击后需要相册读取权限。部分 Android 应用商店要求"权限申请前先声明"，官方提供了一个权限提示插件来处理
连续扫码如需"一直扫、扫完接着扫"，官方推荐改用 camera 组件（它提供扫码模式）
可定制性Android / iOS 端的扫码界面本身是一个开源的 uvue 页面（内嵌 camera 组件），可以自行改样式；鸿蒙与小程序直接调用平台扫码 API，界面不可自定义
💡
一个真实项目的常见做法：

扫码签到通常不会只让用户"扫一下"就完事，而是： 扫码拿到内容 → 校验内容格式（是不是本校的码）→ 请求接口核销 → 显示签到结果与时间。 把"校验 + 核销"放在服务端，客户端只负责"扫码 + 展示结果"—— 否则改一个二维码格式就要发新版本。

10.4

系统与设备信息：把 App 调成"适配这台设备"

20 分钟 · 讲授 + 演练

官方把"读信息"这件事拆成了几个专用 API（比一个巨大的 getSystemInfo 更清晰）：

API读什么典型用途
uni.getDeviceInfo()设备层面信息（deviceBrand / deviceModel / system / osTheme / deviceId 等）机型适配、统计、读取系统深浅色主题。注意 brand / model 已废弃（仅向下兼容），字段名请用 deviceBrand / deviceModel
uni.getAppBaseInfo()应用层面信息（appVersion、appTheme、hostTheme、uniPlatform 等）版本判断、应用主题与宿主主题（第 3 章用过）。appTheme 为 auto 时要再去读 osTheme；appTheme 仅 App 平台有
uni.getWindowInfo()窗口与屏幕信息（screenWidth / windowWidth / statusBarHeight / safeArea / safeAreaInsets / cutoutArea 等）自定义导航栏、安全区与刘海适配。它的宽高取的是栈顶页面，建议在 onReady 之后读取
uni.getSystemInfo()综合信息（老接口）官方说明：该 API 涉及的信息越来越多、查询速度会变慢，因此拆出了上面三个新 API（新 API 信息更全）；微信小程序已不推荐使用它
uni.getAppAuthorizeSetting()应用的授权设置（是否允许相册/相机/定位等）进入页面先判断"要不要引导用户授权"
uni.getSystemSetting()系统设置（蓝牙、定位、WiFi 开关等）判断"系统定位开关是否打开"
uni.openAppAuthorizeSetting()跳转到系统授权管理页引导用户去开权限（10.5 会用到）
uni.isSimulator()是否运行在模拟器上防作弊、区分测试环境
读设备与应用信息（并把主题接回第 3 章） 
<script setup>
  const deviceLabel = ref<string>('')
  const themeLabel = ref<string>('')

  onLoad(() => {
    // ① 设备信息
    const dev = uni.getDeviceInfo()
    // 注意：brand / model 已废弃（仅向下兼容），现在用 deviceBrand / deviceModel
    deviceLabel.value = dev.deviceBrand + ' ' + dev.deviceModel + ' · ' + dev.system

    // ② 应用与主题信息（与第 3 章的暗黑模式配合）
    const app = uni.getAppBaseInfo()
    // appTheme：应用自己的主题；hostTheme：浏览器/小程序宿主的主题
    themeLabel.value = 'appTheme=' + app.appTheme

    // ③ 设备侧的系统主题（App 平台）
    const osTheme = dev.osTheme
    console.log('系统主题：', osTheme, ' 应用主题：', app.appTheme)

    // ④ 窗口信息：自定义导航栏时经常要读状态栏高度
    const win = uni.getWindowInfo()
    console.log('屏幕宽高：', win.screenWidth, win.screenHeight)
  })
</script>
!
两条实践经验：

① 信息类 API 只在需要时读、并缓存到变量里，不要在每个函数里重复调用—— 它们虽然不慢，但本质是桥接调用； ② 不要用设备型号去做"业务判断"（例如"华为机型就怎样"）， 而应该依据能力判断（屏幕尺寸、是否支持某 API）。按机型写分支的代码， 在新机型上市时会变成无法维护的泥潭。

10.5

权限：把"失败"变成"可引导"

15 分钟 · 讲授 + 演练

设备能力最容易被忽略、也最影响体验的一环就是权限。官方为此提供了几个专门的 API： uni.getAppAuthorizeSetting()（看有没有权限）、 uni.requestSystemPermission()（申请权限）、 uni.openAppAuthorizeSetting()（跳到系统设置页）、 uni.createRequestPermissionListener()（监听权限申请结果）。

用户的处境技术上表现应该怎么做
自己取消了操作 chooseImage 返回 errCode 1101001 什么都不提示，安静返回即可（这是他自己的选择）
从没授权过 errCode 1101005（未获取权限） 弹一个说明"为什么需要这个权限"的对话框，用户点确认后发起申请或跳到设置页
之前拒绝过（系统不再弹窗） 再次申请无反应 / 直接返回失败 只能引导用户去系统设置里手动打开（uni.openAppAuthorizeSetting()）
系统开关本身是关的（如定位服务） uni.getSystemSetting() 显示关闭 提示"请打开系统定位服务"，而不是怪用户没授权本应用
✕
三个会被用户和审核同时嫌弃的做法：

① 一进 App 就要一堆权限——应该"用到时才申请"，并在申请前说明用途； ② 把"用户取消"也弹成错误——用户点了取消还要被红字提醒，体验很差； ③ 不给权限就不让用——除了扫码这类"没权限真的没法用"的场景， 其他能力都应该能降级（例如不能选头像就先用默认头像）。 另外部分 Android 应用商店要求在申请前声明权限用途，官方提供了对应的提示插件与做法。

10.6

常用设备能力速查（按需求找 API）

10 分钟 · 讲授

下面这些都在官方「设备」类目下。这里只给"需求 → API"，具体参数与平台差异请查对应页面（呼应附录 A 的用法）。

想做的事API备注
复制/读取剪贴板uni.setClipboardData / uni.getClipboardData第 5 章做过"长按复制取件码"。新版安卓读取剪贴板是单独权限，鸿蒙读需要 READ_PASTEBOARD 权限
拨打电话uni.makePhoneCallphoneNumber 必填；鸿蒙需受限权限
震动反馈uni.vibrateShort / uni.vibrateLongvibrateShort 的 type 必填（heavy / medium / light）；Web 与支付宝不支持
读/设屏幕亮度uni.getScreenBrightness / uni.setScreenBrightnessvalue 范围 0–1；还有保持常亮的 setKeepScreenOn。"扫码时自动调亮"很实用
读电池电量uni.getBatteryInfo / getBatteryInfoSync它属于扩展 API，需要先下载对应插件（官方 uni-getbatteryinfo），不是开箱即用
定位与地图uni.getLocation / chooseLocation / openLocation注意：gcj02 坐标或逆地理编码需要第三方地图 Key（需商业授权），详见下方提示
是否模拟器uni.isSimulator()测试环境判断（注意：作为字段的 isSimulator 已废弃，改用这个方法）
监听截屏截屏事件 API隐私页面提醒；注意清理监听
内存告警内存告警 API大图/长列表场景下做降级
WiFi、罗盘、加速度计、陀螺仪对应设备 API趣味项目（校园指南针、摇一摇）用得上；鸿蒙读网络信息需权限
联系人、日历联系人与日历 API需权限，课程项目用得少
安装 APK安装 APK API企业内部分发场景
!
特别提醒：定位是"要提前准备"的能力，不是开箱即用。

uni.getLocation 的 provider 默认是 system（系统定位，免 Key，但只能拿到 wgs84 坐标）；要用国内地图常见的 gcj02 坐标系，或者需要逆地理编码（把坐标换成地址）， 就必须接第三方地图 SDK，而这需要在对应地图厂商申请 Key，且涉及商业授权。 uni.chooseLocation 在 App 与 Web 端同样必须在 manifest.json 里配置地图模块与 Key。 另外 geocode（逆地理）只在 iOS 系统定位下支持，Android / 鸿蒙不支持。 结论：做"签到定位"之前先确认你有没有 Key；没有就先只拿经纬度做展示。 顺带一提，uni.openLocation 从 HBuilderX 5.11 起已内置，不需要再单独引入插件。

💡
怎么快速确认"某个能力官方有没有"：

打开官方 API 文档左侧目录，按分类扫一眼（设备/媒体/位置/文件…）。 这比在搜索引擎里翻十篇博客快得多，而且能立刻看到兼容性表格—— 这张表会告诉你"这个 API 在 App 端到底支持不支持"。 这也是本课程反复强调的：先查文档，再写代码。

10.7

一个容易踩的坑：uni API 属于"全局逻辑层"

10 分钟 · 讲授

读到这里你已经用了很多 uni.xxx。官方特别强调了一点： uni.xxx 的 API 运行在全局逻辑层，不与代码所在的页面文件绑定； 其中一部分"与页面有关"的 API，实际操作的是页面栈栈顶页面（不含 dialogPage）。

场景会发生什么怎么避免
新页面 onPageShow 还没触发时调用 uni.getElementById('abc') 栈顶还是上一个页面，于是去上一个页面里找元素（找不到或找错） 把取元素的逻辑放到 onReady 之后
老页面的定时器里调用 uni.getElementById('abc')，期间用户打开了新页面 定时器还在跑，而栈顶已经变成新页面 → 开始从新页面找元素 页面卸载时清掉定时器（第 7 章的 onUnload）
需要精确操作"我这个页面" 用全局 API 时依赖"当前栈顶是谁" 用 UniPage 对象：组合式里 getCurrentInstance()?.proxy?.$page.getElementById('abc')
ⓘ
受这条规则影响的常见 API（官方列举）：

uni.getElementById、uni.setNavigationBarColor、uni.setNavigationBarTitle、 uni.showNavigationBarLoading / hideNavigationBarLoading、 uni.startPullDownRefresh / stopPullDownRefresh、uni.pageScrollTo 等。 另外有些 API（如 uni.createVideoContext(id, component)）可以传第二个参数指定页面，不传就默认找栈顶。 小程序端没有 UniPage 对象，只能用这些全局 API，所以更要注意这个边界情况。

10.8

UTS 插件入门：当内置能力不够用时

20 分钟 · 讲授

官方在 API 概述里给出了一句很关键的定位： UTS 可以直接调用 Android / iOS / 鸿蒙的原生 API， 所以系统能力和第三方 SDK 都能在 UTS 里调起来。 但紧接着官方也说了"规范做法"：

ⓘ
官方原意（意译）：

虽然在部分模式下可以在页面里直接调用原生 API，但这并不规范； 规范的做法是把原生能力封装成 uni_modules 形式的 uts 插件—— 这样方便共享、方便跨平台。 换句话说：页面里写业务，原生能力住在插件里。

你要做的事推荐做法为什么
官方已有对应 API 直接用 uni.xxx() 跨端差异已被官方抹平，最省事
官方没有，但插件市场有 从插件市场安装 uts 插件（勾选支持 uni-app x），放进 uni_modules 别人已经填过坑；注意看插件的兼容性说明与更新时间
都没有，需要对接原生 SDK / 平台专属能力 自己写 uts 插件：在 uni_modules 里用 UTS 调用原生 API（必要时混编 Kotlin / Swift / ArkTS） 官方提供了 UTSAndroid / UTSiOS / UTSHarmony 平台专用 API 文档可直接查
都不确定该怎么写插件 看官方 uts 插件的目录结构与写法：uni_modules/插件id/utssdk/ 下有 interface.uts（声明对外 API，必需）、 index.uts（跨平台入口），以及 app-android / app-ios / app-harmony / web 各平台目录 原生调用写法形如 import Build from 'android.os.Build'；UTSAndroid / UTSiOS / UTSHarmony 是平台内置对象，不用 import
想用别人做好的 uts 插件 装到 uni_modules 后按官方示例引入：import { myApi } from "@/uni_modules/uts-api"（uvue 里可同时引入类型） 官方说明：目前仅支持通过 HBuilderX 创建和使用 UTS 插件，不支持通过 cli 方式
不确定该怎么写 参考官方开源的 uni-api 仓库——你每天用的 uni API 就是用 UTS 写的 照着官方实现改，是最可靠的学习路径
!
三件与第 1 章呼应的历史包袱，别踩：

① uni-app x 不再支持 plus 和 weex 的 API——老教程里的 plus.xxx 写法在这里一律不可用； ② 官方说明 uni-app x 里"原生语言插件"那套（nativeplugins）已不再是主路线， 原生能力统一走 uts 插件； ③ 官方也提供独立的 utssdk 目录来存放 uts 插件，但官方更推荐 uni_modules 方式——本课程按推荐方式讲。

💡
给大学生的现实建议：

课程项目里尽量不要自己写 uts 插件——它需要你同时懂目标平台的原生开发， 这是另一个学期的内容。 优先顺序永远是：内置 API → 插件市场 → 调整需求。 把"必须写插件"当成加分项而不是必选项； 如果真要做，官方提供了 AI 辅助开发 uts 插件的路径（uni-agent）， 但"看得懂自己调用的是什么"这条底线不能丢——第 10 章开头就说过： AI 可以帮助你写代码，但线上出事时担责的是你。

✓
本章验收标准：

能独立完成"选图 → 预览 → 压缩 → 上传"与"扫码 → 处理结果"两条链路； 遇到权限失败能分别处理"取消"与"未授权"； 并且在遇到一个新能力需求时，能按"内置 → 插件 → 自写"的顺序做判断。
