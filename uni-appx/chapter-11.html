11.1

第一步：把一句话需求拆成功能清单

15 分钟 · 讲授 + 讨论

需求原话只有一句："做一个校园课程表 App"。 如果直接开始写代码，结果一定是"写着写着发现漏了功能，然后到处补洞"。 专业做法是先写清用户故事，再翻译成功能清单，最后明确不做什么。

用户故事（谁、在什么场景、想干什么）翻译成功能用到哪一章
作为学生，我早上出门前想知道"今天有哪些课、在哪上"首页显示今日课程卡片（按时间排序 + 空态）4（computed）、2（布局）
作为学生，我想看整周的课表，像教务系统那样一格一格课表页：7 列 × 节次的网格2（flex 网格）、11.5
作为学生，我想按周查看（第 3 周、第 8 周，单双周课不同）周次切换 + 周次过滤4（派生）、7（状态记忆）
作为学生，我要把自己课表录入进去，之后还能改和删添加/编辑/删除课程表单（含校验）5（表单）、6（组件）、9（存储）
作为学生，我关掉 App 明天再打开，课表不能丢本地持久化 + 启动恢复9（存储）
作为学生，我晚上用手机，界面别刺眼深浅色适配3（主题）
!
明确"不做什么"，比列功能更重要：

本项目不做：账号登录（第 12 章再做）、教务系统自动导入（涉及爬虫与合规）、 上课提醒推送（需要推送服务）、多端云同步（需要后端）。 把这些写进"本期不做"，你在开发过程中就不会被它们打断， 答辩时也能主动说明"这是有意识的取舍"——这比"忘了做"高一个层次。

💡
页面清单（做完这 4 个页面，项目就成型了）：

① 首页（tab）：今日课程 + 快捷入口；② 课表页（tab）：周网格； ③ 我的（tab）：设置项（周次、深浅色、清空数据）； ④ 添加/编辑课程页（非 tab，用 navigateTo 进入）。 注意 tabBar 页面只能用 switchTab 跳，而"添加课程页"要用 navigateTo——第 7 章的规则在这里第一次真实用上。

11.2

第二步：数据建模——先把"一门课"说清楚

20 分钟 · 讲授

课表项目最关键的思考在建模上。请先回答："一门课"需要哪些字段才能画到格子里？ 想清楚这一点，后面的渲染与统计都会变得很顺。

types/course.ts —— 数据模型（先定义类型，再写代码） 
// 一门课
export type Course = {
  id: number,              // 唯一标识（列表 :key 用它，删除也用它）
  name: string,            // 课程名，如"移动应用开发"
  teacher: string,         // 教师
  room: string,            // 地点，如"实验楼 B302"
  day: number,             // 星期几：1=周一 … 7=周日
  startSection: number,    // 从第几节开始：1–6
  sectionCount: number,    // 连上几节：1 或 2（连堂课）
  weeks: number[],         // 出现在哪些周：如 [1..16]，单周课就是 [1,3,5,...]
  colorKey: string         // 卡片配色标识（不存色值，存"用哪个令牌"）
}

// 一天里的节次（本项目按 6 节设计，可按你学校改）
export const SECTION_COUNT = 6

// 星期表头
export type DayItem = { 'value': number, 'label': string }

export const DAYS: DayItem[] = [
  { 'value': 1, 'label': '周一' },
  { 'value': 2, 'label': '周二' },
  { 'value': 3, 'label': '周三' },
  { 'value': 4, 'label': '周四' },
  { 'value': 5, 'label': '周五' },
  { 'value': 6, 'label': '周六' },
  { 'value': 7, 'label': '周日' }
]
设计决策为什么这么定如果定错了会怎样
用 day + startSection + sectionCount，而不是"第几行第几列" 字段表达的是业务含义；行列坐标可以由它们算出来 存坐标后，改一次节次总数（6 节改 8 节）就要迁移全部数据
weeks 存周次数组而不是"1-16周/单双周"字符串 渲染时只需 weeks.includes(currentWeek)，逻辑最简单 存字符串就要到处写解析逻辑，最容易在单双周上出错
colorKey 存"用哪个令牌"而不是具体色值 深浅色切换时颜色自动跟着走（第 3 章的令牌思想） 存死色值后，深色模式下一片刺眼或看不清
id 用自增数字（或时间戳） v-for 的 :key 需要唯一稳定值（第 2 章强调过） 用 index 当 key，删除后会出现状态错位
utils/timetable-store.ts —— 存储设计（第 9 章的规范用法） 
export const KEY_COURSES = 'app_courses'          // 课程列表（JSON 字符串）
export const KEY_WEEK = 'app_week'                // 当前查看第几周
export const KEY_TERM_START = 'app_term_start'    // 开学日期（用于推算"现在第几周"）

// 读课程列表：解析失败就当空列表，绝不让脏数据把页面搞崩
export const loadCourses = (): Course[] => {
  const raw = uni.getStorageSync(KEY_COURSES) as string
  if (raw.length == 0) return []
  try {
    return JSON.parse(raw) as Course[]
  } catch (e) {
    console.log('课程数据解析失败，按空处理')
    return []
  }
}

// 写课程列表
export const saveCourses = (list: Course[]) => {
  uni.setStorageSync(KEY_COURSES, JSON.stringify(list))
}

// 当前周次（默认第 1 周）
export const loadWeek = (): number => {
  const v = uni.getStorageSync(KEY_WEEK) as number
  return (v != null && v > 0) ? v : 1
}

export const saveWeek = (week: number) => {
  uni.setStorageSync(KEY_WEEK, week)
}

// 由开学日期推算"今天第几周"——让用户不用手动找周次
export const calcCurrentWeek = (): number => {
  const startRaw = uni.getStorageSync(KEY_TERM_START) as string
  if (startRaw.length == 0) return 1
  const start = new Date(startRaw)
  const days = Math.floor((Date.now() - start.getTime()) / (24 * 3600 * 1000))
  const week = Math.floor(days / 7) + 1
  return week > 0 ? week : 1
}

为什么这个项目不需要服务端？

课表是"只有本人关心、且不会多人同时修改"的数据，放本地最合适： 没有网络也能用、没有并发问题、没有隐私顾虑。 判断"要不要后端"的标准从来不是"看起来专业不专业"，而是"数据是否需要在多设备/多人之间共享"。 这条判断以后你会反复用到。

11.4

首页：把"今天有什么课"算出来

20 分钟 · 讲授 + 演练

首页不需要新知识，它是第 4 章"派生数据"思想的最佳练习： 你只维护"课程列表 + 当前周次"两个状态，"今天的课"完全是算出来的。

utils/timetable-logic.ts —— 纯逻辑函数（好测试、好复用） 
/* 把"与界面无关的算法"集中放在这里：页面只负责展示，逻辑放这里便于复用与排查 */

// 今天星期几（1=周一 … 7=周日）。注意：JS 的 getDay() 里 0 才是周日
export const todayDay = (): number => {
  const d = new Date().getDay()
  return d == 0 ? 7 : d
}

// 某一天的课程（按开始节次排序）
export const coursesOfDay = (list: Course[], day: number, week: number): Course[] => {
  return list
    .filter((c) => c.day == day && c.weeks.includes(week))
    .sort((a, b) => a.startSection - b.startSection)
}

// 以当前周次为基准，找出"本周有课"的全部课程
export const coursesOfWeek = (list: Course[], week: number): Course[] => {
  return list.filter((c) => c.weeks.includes(week))
}

// 一节课的结束节次（用于显示"第1-2节"）
export const endSection = (c: Course): number => c.startSection + c.sectionCount - 1

// 把节次翻译成人话时间（按你学校作息改）
export const sectionTime = (section: number): string => {
  const table = ['08:00', '08:55', '10:00', '10:55', '14:00', '14:55']
  return section >= 1 && section <= table.length ? table[section - 1] : ''
}

<script setup>
  import { loadCourses, loadWeek, calcCurrentWeek } from '@/utils/timetable-store'
  import { todayDay, coursesOfDay, endSection, sectionTime } from '@/utils/timetable-logic'

  const list = ref<Course[]>([])
  const week = ref<number>(1)

  // 派生数据：今天的课（不单独存，永远不会忘记同步）
  const todayCourses = computed<Course[]>(() => {
    return coursesOfDay(list.value, todayDay(), week.value)
  })

  const dayLabel = computed<string>((): string => {
    const label = DAYS[todayDay() - 1].label
    return label
  })

  const load = () => {
    list.value = loadCourses()
    // 优先用"由开学日期推算的周次"，用户就不用每周手动调
    const auto = calcCurrentWeek()
    week.value = auto > 1 ? auto : loadWeek()
  }

  onLoad(() => { load() })

  // 每次回到首页都刷新：从"添加课程"返回时才能看到新数据（第 7 章的规则）
  onPageShow(() => { load() })

  onPullDownRefresh(() => {
    load()
    uni.stopPullDownRefresh()
  })

  const goAdd = () => {
    // 非 tabBar 页面：用 navigateTo
    uni.navigateTo({ 'url': '/pages/course-edit/edit' })
  }
</script>

为什么要单独建一个 timetable-logic.ts？

因为"哪一天有哪些课""第几周生效""节次对应几点"这类算法与界面无关， 把它们抽出来有三个好处：① 页面代码变短；② 首页、课表页、我的页可以共用同一套逻辑（不会出现三处算法不一致）； ③ 出问题时你能确定"要么是逻辑错，要么是渲染错"，而不是一团乱麻。 这也是第 4 章"逻辑抽成函数"的思想在项目里的具体落地。

11.5

课表页：这个项目最难的一块——网格

30 分钟 · 讲授 + 演练

课表本质是一张"7 列（星期）× 6 行（节次）"的表格。在移动端做它有四个要点：

要点做法为什么
固定左侧节次列左列写死宽度（如 44px），右侧 7 列用 flex: 1 平分节次标签宽一点窄一点都无所谓，但 7 列必须等宽
行高一致每一行固定高度（如 76px）行高一致才能让"跨两节的课"看起来是整齐的一大块
判空逻辑放在 computed 里预先构建一个"格子矩阵"，每个格子的字段一定存在（用 empty 标记）避免在模板里写 cell != null 之后再取 cell.name 这种"空值断言"
跨节次课程本课程先用"每格都画 + 圆角拼接"的稳妥方案；进阶再用绝对定位画整块绝对定位涉及 z-index 只在同层兄弟间生效等限制（第 3 章），新手容易卡住
构建"格子矩阵"：让模板彻底变简单 
// utils/timetable-logic.ts（续）
export type Cell = {
  empty: boolean,        // 这一格有没有课（模板只判断它，不做空值断言）
  id: number,
  name: string,
  room: string,
  colorKey: string,
  isFirst: boolean,      // 是不是连堂课的"第一节"（用来决定上方圆角）
  isLast: boolean        // 是不是连堂课的"最后一节"（决定下方圆角）
}

// 构建 [行][列] 的格子矩阵：行=节次，列=星期（与表格的视觉顺序一致）
export const buildGrid = (list: Course[], week: number): Cell[][] => {
  const rows: Cell[][] = []
  for (let s = 1; s <= SECTION_COUNT; s++) {
    const row: Cell[] = []
    for (let d = 1; d <= 7; d++) {
      // 找出"这一格是否被某门课覆盖"
      let hit: Course | null = null
      for (let i = 0; i < list.length; i++) {
        const c = list[i]
        const end = c.startSection + c.sectionCount - 1
        if (c.day == d && c.weeks.includes(week) && s >= c.startSection && s <= end) {
          hit = c
          break
        }
      }
      if (hit == null) {
        row.push({ 'empty': true, 'id': 0, 'name': '', 'room': '', 'colorKey': '', 'isFirst': false, 'isLast': false })
      } else {
        const end = hit.startSection + hit.sectionCount - 1
        row.push({
          'empty': false,
          'id': hit.id,
          'name': hit.name,
          'room': hit.room,
          'colorKey': hit.colorKey,
          'isFirst': s == hit.startSection,
          'isLast': s == end
        })
      }
    }
    rows.push(row)
  }
  return rows
}

进阶方案：用绝对定位画"真正的一大块"

如果你希望连堂课的色块是一个完整的圆角矩形（而不是两格拼起来），做法是： 让网格容器 position: relative，课程块用 position: absolute， 并按公式算位置：top = (startSection - 1) × 行高、 height = sectionCount × 行高 - 间距、 left 由星期序号算（例如 left: 34px + (day - 1) × 列宽）。 要注意第 3 章讲过的限制：z-index 只在同一层兄弟节点之间生效， 而且绝对定位元素不参与 flex 排布，需要你手动算清所有坐标。 建议先用上面"每格都画"的稳妥方案把功能做完，再考虑升级。

!
网格布局最容易出错的三处：

① 忘了给 scroll-view 高度 → 它和内容一样高、滚不动（第 2 章的坑）； ② 7 列用固定宽度而不是 flex: 1 → 小屏挤爆、大屏留白； ③ 课程块直接写死色值 → 深色模式下白字看不清（应该走令牌变量）。

添加 / 编辑 / 删除：把表单与存储接起来

一个页面同时承担"新增"和"编辑"两种职责，靠 url 参数区分： 带 id 就是编辑，不带就是新增（第 7 章的传参用法）。

<template>
  <view class="page">
    <view class="form-item">
      <text class="label">课程名</text>
      <input class="field" :value="form.name" placeholder="如：移动应用开发" @input="onNameInput" />
    </view>
    <text v-if="nameError.length > 0" class="error">{{ nameError }}</text>

    <view class="form-item">
      <text class="label">教师</text>
      <input class="field" :value="form.teacher" placeholder="如：张老师" @input="onTeacherInput" />
    </view>

    <view class="form-item">
      <text class="label">地点</text>
      <input class="field" :value="form.room" placeholder="如：实验楼 B302" @input="onRoomInput" />
    </view>

    <!-- 星期：底部选择器（第 5 章） -->

      <view class="form-item">
        <text class="label">星期</text>
        <text class="value">{{ dayLabels[dayIndex] }}</text>
      </view>
    </picker>

    <!-- 起始节次 -->
    <picker mode="selector" :range="sectionLabels" :value="startIndex" @change="onStartChange">
      <view class="form-item">
        <text class="label">开始节次</text>
        <text class="value">{{ sectionLabels[startIndex] }}</text>
      </view>
    </picker>

    <!-- 连上几节 -->
    <picker mode="selector" :range="countLabels" :value="countIndex" @change="onCountChange">
      <view class="form-item">
        <text class="label">连上节数</text>
        <text class="value">{{ countLabels[countIndex] }}</text>
      </view>
    </picker>

    <!-- 周次：用开关做"单双周"最省事（真实场景里比选 16 个周次友好得多） -->
    <view class="form-item">
      <text class="label">仅单周上课</text>
      <switch :checked="oddOnly" foreColor="#2F6BFF" @change="onOddChange" />
    </view>

    <view class="form-item">
      <text class="label">卡片配色</text>
      <view class="colors">
        <view
          v-for="c in colorKeys"
          :key="c"
          class="color-dot"
          :class="['dot-' + c, form.colorKey == c ? 'dot-active' : '']"

    <button v-if="isEdit" class="del" @click="confirmDelete">删除这门课</button>

<script setup>
  import { loadCourses, saveCourses } from '@/utils/timetable-store'
  import { DAYS, SECTION_COUNT } from '@/types/course'

  const dayLabels = ref<string[]>(DAYS.map((d) => d.label))
  const sectionLabels = ref<string[]>(['第 1 节', '第 2 节', '第 3 节', '第 4 节', '第 5 节', '第 6 节'])
  const countLabels = ref<string[]>(['1 节', '2 节', '3 节'])
  const colorKeys = ref<string[]>(['1', '2', '3', '4'])

  const isEdit = ref(false)
  const editId = ref<number>(-1)

  // 表单状态：一个 reactive 对象装所有字段（第 4 章）
  const form = reactive({
    'name': '',
    'teacher': '',
    'room': '',
    'day': 1,
    'startSection': 1,
    'sectionCount': 1,
    'colorKey': '1'
  })

  const oddOnly = ref(false)
  const dayIndex = computed(() => form.day - 1)
  const startIndex = computed(() => form.startSection - 1)
  const countIndex = computed(() => form.sectionCount - 1)

  onLoad((options: OnLoadOptions) => {
    const idStr = options['id'] ?? ''
    if (idStr.length > 0) {
      // 编辑模式：按 id 把已有数据填进表单
      isEdit.value = true
      editId.value = Number(idStr)
      const found = loadCourses().find((c) => c.id == editId.value)
      if (found != null) {
        form.name = found.name
        form.teacher = found.teacher
        form.room = found.room
        form.day = found.day
        form.startSection = found.startSection
        form.sectionCount = found.sectionCount
        form.colorKey = found.colorKey
        // 判断是不是"只有单周"
        oddOnly.value = found.weeks.every((w) => w % 2 == 1)
      }
    }
  })

  const onNameInput = (event: UniInputEvent) => { form.name = event.detail.value }
  const onTeacherInput = (event: UniInputEvent) => { form.teacher = event.detail.value }
  const onRoomInput = (event: UniInputEvent) => { form.room = event.detail.value }
  const onDayChange = (event: UniPickerChangeEvent) => { form.day = (event.detail.value as number) + 1 }
  const onStartChange = (event: UniPickerChangeEvent) => { form.startSection = (event.detail.value as number) + 1 }
  const onCountChange = (event: UniPickerChangeEvent) => { form.sectionCount = (event.detail.value as number) + 1 }
  const onOddChange = (event: UniSwitchChangeEvent) => { oddOnly.value = event.detail.value }
  const pickColor = (key: string) => { form.colorKey = key }

  // 校验：错误只在"填过之后"才提示（第 5 章的体验细节）
  const nameError = computed(() => form.name.length > 0 && form.name.length < 2 ? '课程名至少 2 个字' : '')

  // 不能"连上课时超出当天节次"
  const sectionValid = computed(() => form.startSection + form.sectionCount - 1 <= SECTION_COUNT)

  const canSave = computed(() => form.name.length >= 2 && sectionValid.value)

  // 由"是否单周"生成周次数组
  const buildWeeks = (): number[] => {
    const arr: number[] = []
    for (let w = 1; w <= 20; w++) {
      if (oddOnly.value) {
        if (w % 2 == 1) arr.push(w)
      } else {
        arr.push(w)
      }
    }
    return arr
  }

  const save = () => {
    if (!canSave.value) return
    const list = loadCourses()

    if (isEdit.value) {
      // 编辑：整体替换这一项（保持 :key 稳定）
      const next = list.map((c) => {
        if (c.id != editId.value) return c
        return {
          'id': c.id,
          'name': form.name,
          'teacher': form.teacher,
          'room': form.room,
          'day': form.day,
          'startSection': form.startSection,
          'sectionCount': form.sectionCount,
          'weeks': buildWeeks(),
          'colorKey': form.colorKey
        } as Course
      })
      saveCourses(next)
    } else {
      // 新增：自增 id（取现有最大 id + 1）
      let maxId = 0
      for (let i = 0; i < list.length; i++) { if (list[i].id > maxId) maxId = list[i].id }
      const c: Course = {
        'id': maxId + 1,
        'name': form.name,
        'teacher': form.teacher,
        'room': form.room,
        'day': form.day,
        'startSection': form.startSection,
        'sectionCount': form.sectionCount,
        'weeks': buildWeeks(),
        'colorKey': form.colorKey
      }
      saveCourses(list.concat(c))
    }

    uni.showToast({ 'title': '已保存', 'icon': 'none' })
    // 返回上一页；上一页的 onPageShow 会自动刷新（第 7 章的机制）
    setTimeout(() => { uni.navigateBack() }, 600)
  }

  const confirmDelete = () => {
    uni.showModal({
      'title': '删除课程',
      'content': '删除后无法恢复，确定吗？',
      'confirmColor': '#E5484D',
      'success': (r) => {
        if (!r.confirm) return
        const next = loadCourses().filter((c) => c.id != editId.value)
        saveCourses(next)
        uni.showToast({ 'title': '已删除', 'icon': 'none' })
        setTimeout(() => { uni.navigateBack() }, 400)
      }
    })
  }
</script>

📌 这个项目你真正学到的，浓缩成 6 句话

做项目的第一步不是打开编辑器，而是把需求拆成用户故事与功能清单，并明确"不做什么"； 数据建模决定了后面所有代码的难度——存业务含义（星期 / 起始节次 / 周次数组 / 配色标识），不要存坐标与死色值； 页面只维护"课程列表 + 当前周次"两个源状态，今天的课、本周的课、格子矩阵全部由 computed 派生； 表格类界面的套路是固定左侧标签列 + 右侧 flex: 1 等分 + 固定行高， 并且把判空逻辑放进 computed，让模板只判断 empty 字段； 表单页用 id 参数区分新增与编辑，校验用 computed 驱动按钮 :disabled，危险操作必须二次确认； 最后 40% 的价值在打磨：深浅色走令牌、空态写文案、状态记忆（第几周）、安全区、点击反馈， 再用"让同学自己操作"的方式验收。

用户故事拆解 明确不做 数据建模 周次数组 colorKey 令牌 存储设计 tabBar 骨架 computed 派生 格子矩阵 fixed 左列 + flex 等分 连堂课圆角拼接 新增/编辑共用一页 computed 校验 二次确认删除 onPageShow 刷新 打磨与验收
