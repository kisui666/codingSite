编译错误与真机问题排错手册

排错能力比写代码能力更能拉开差距。这一页把 uni-app x 学习过程中最常出现的 40 多个症状 整理成"症状 → 原因 → 解决"的速查表：搜报错关键词、搜现象描述（例如"真机白屏""颜色改不动"）都能命中。 表格上方还给了五步排查流程，遇到没收录的问题也能自己定位。

B.1

先分层，再定位：五步排查流程

遇到任何问题都先用它

新手排错最大的问题是"到处乱改"：改一行、跑一次、还是不对、再改一行…… 最后既没找到原因，还把原来能跑的代码改坏了。正确的做法是先判断问题属于哪一层，再用排除法缩小范围。

1

🔍 先看控制台，别猜

30 秒

HBuilderX 底部的控制台会打印编译信息与运行日志。有红字就先解决红字——它给的往往就是文件名与行号， 点击日志还能跳到对应代码行。没有报错的问题，才需要往下走。

2

🧱 判断阶段：是编译期还是运行期

1 分钟

编译期：页面根本起不来 / 报"编译失败"。多半是语法、JSON 格式、路径、类型问题。 运行期：页面出来了但报错、白屏、点了没反应。多半是数据、事件、API 调用问题。 无报错：界面不对但程序正常。多半是样式规则、跨端差异、布局高度问题。

3

✂️ 二分法与注释法缩小范围

2 分钟

把可疑代码注释掉一半再跑：问题还在，说明问题在剩下的一半里；问题消失，说明就在注释掉的那一半里。 重复三四次就能锁定到具体几行。这是最有效的通用手段，比"凭感觉改"快十倍。

4

📱 换端复现，判断是否跨端差异

2 分钟

浏览器正常、真机不对 → 几乎可以确定是App 端不支持该写法或平台差异（对照附录 A 的"危险写法清单"）。 两端都不对 → 是逻辑问题，回到第 3 步。

5

📚 用"现象 + 关键词"去查，而不是抄代码

5 分钟

搜索时把现象和关键词一起写，例如"uni-app x 真机 图片 不显示 static"、 "uvue 组件 全局 class 不生效"。由于 uni-app x 版本迭代快， 优先看官方文档与官方示例工程，其次看社区问答的时间戳是否够新。 搜到的老 uni-app（非 x）方案要谨慎套用。

💡
一个能立刻止损的习惯：

在动手改之前，先让当前能跑的状态"可回退"（提交一次 git，或复制一份文件）。 排错时最怕的不是改错，而是改到最后连"原来是什么样"都记不清了。

B.2

症状速查表

按需查阅
症状最可能的原因怎么解决分类
页面根本打不开 / 提示找不到页面pages.json 里没注册，或 path 写了 .uvue 后缀、路径与文件目录不一致path 不写后缀（pages/index/index），并且要注册；数组第一项是启动页编译
报 JSON 解析失败 / Unexpected tokenpages.json、manifest.json 里有多余逗号或写了注释删掉最后一项后面的逗号，去掉所有注释（JSON 不支持注释）编译
新建的页面访问不到只创建了 .uvue 文件，没登记到 pages.json在 pages 数组里加一项，路径不带后缀编译
改了代码页面没变化热更新失效 / 编译缓存异常重新点一次"运行"；仍无效就停止运行再重新运行；必要时清理工程缓存编译
打包时莫名失败、找不到文件工程路径含中文、空格或特殊字符把工程移到纯英文无空格路径（如 D:\code\campus-app）后重新打开编译
提示某个组件不存在 / 无法解析组件文件位置或命名不符合自动引入规则放到项目的 components 目录，按组件命名规则命名；不确定就显式 import（第 6 章详讲）编译
提示类型不匹配 / 缺少类型变量没有类型标注，或赋了与声明不一致的值给数据写上类型，例如 ref<string>('')、ref<Notice[]>([])；数组与对象一定要写元素类型编译
提示 import 找不到模块路径写错（相对路径层级）或模块不在支持的目录核对相对路径；公共逻辑建议放在项目内的工具目录里统一引用编译
文字颜色 / 字号改不动样式写在了 view 上，而 App 端样式不继承把文字样式写到 text 组件（或它的 class）上样式
元素全都竖着排，想要横排uvue 默认 flex-direction: column显式写 flex-direction: row样式
元素之间的间距没生效用了 gap / row-gap，App 端不支持改成 margin；网格布局给格子加 padding样式
整块样式完全不生效用了标签选择器（text {}）、#id、属性选择器、*只用 class 选择器；class 名只允许字母数字下划线短横线样式
::before / :active 一点效果都没有App 端不支持伪元素与伪类装饰用真实的 view 节点；点击态用组件的 hover-class 属性样式
点击没有任何反馈hover-class 默认值是 none显式指定 hover-class="xxx" 并在样式里定义该类样式
放进自定义组件后样式全没了组件默认隔离策略是 isolated，引用不到全局 / 页面 class组件里声明 defineOptions({ styleIsolation: 'app' })，或用 externalClasses 开放定制口（第 3 章）样式
同名 class 的覆盖关系和我预期相反优先级规则与 Web 不同优先级：内联 style > class；同名合并：页面 > 组件 > 全局；同权重时按组件 class 属性书写顺序，后写的赢样式
rem / em 不生效官方长度单位只列了 px、rpx 与百分比字号与间距用 px（推荐），需要等比缩放时用 rpx样式
calc() 计算结果不对或不生效官方对 App 端 calc 的说明前后矛盾避开 calc：用 margin / padding 补足，或改成固定值；确实要用先在真机验证样式
深色模式下颜色没跟着变没有用媒体查询 / CSS 变量，或版本低于要求用 @media (prefers-color-scheme) + CSS 变量（App 端需 HBuilderX 5.25+ 蒸汽模式）；更早版本用监听 + 动态 class样式
scoped 写了没效果非 Web 平台不支持 css scoped删掉 scoped，改用官方样式隔离策略管理范围样式
真机白屏，控制台有红字运行期报错，页面没渲染出来看控制台第一条报错（后面的往往是它的连锁反应），按文件行号定位；用注释法二分运行
白屏但控制台没有任何报错页面路径错了；或根节点高度为 0（内容存在但看不见）先核对 pages.json 的启动页；再检查页面根节点是否写了 flex: 1运行
页面有内容但只占屏幕一点点根节点没有 flex: 1，高度由内容决定页面最外层 view 加 flex: 1 并用一个 class 设背景色运行
报错 undefined is not an object / 读不到属性数据还没拿到就渲染了，或初值是 null给响应式数据合理初值（空数组 / 空字符串），渲染前用 v-if 判断运行
点击按钮没有任何反应写成了 onclick，或函数名拼错，或被上层元素挡住用 @click="fn"（写函数名，不加括号）；检查是否有绝对定位元素覆盖运行
控制台里看不到 console.log看错了位置（在看浏览器控制台，而代码跑在真机）日志在 HBuilderX 底部控制台；真机上可用 uni.showModal 直接显示结果运行
页面切换后报错 / 定时器还在跑页面卸载时没有清理定时器或监听在 onUnload / 组件卸载钩子里 clearInterval、取消监听运行
改了变量，界面完全不变改的是普通变量而不是响应式数据，或忘了写 .value用 ref 声明并在脚本里通过 xxx.value 读写；模板里直接写变量名数据
数组 push 之后界面没更新整体替换比原地修改更可靠改成整体赋值：list.value = list.value.concat(item)，或先取出数组再赋值回去数据
列表删除 / 排序后内容错位、状态串行v-for 的 :key 用了 index把 :key 换成唯一且稳定的值（后端 id 最理想）数据
列表项里的输入框内容跑到了别的行同上，组件状态被复用到错误的项上同上；不要用 index、也不要用可能重复的字段当 key数据
计算属性不更新它依赖的数据不是响应式的确认依赖项都由 ref / reactive 声明数据
watch 不触发监听的目标写错，或对象内部变化需要更深的监听确认监听的是响应式数据本身；监听对象内部字段时直接监听那个字段，或打开深监听数据
页面返回后数据丢失 / 没有刷新数据只在 onLoad 里取过一次，返回时不会重新执行把"每次显示都要刷新"的逻辑放到 onPageShow；或返回值给上一页（第 7 章）数据
请求回来的数据渲染报错接口结构与假设不一致（字段名、层级、空值）先 console.log 打印完整返回结构再写渲染代码；对空数组做兜底数据
真机运行列表里看不到手机USB 线只能充电、手机没点"允许调试"、缺驱动、手机处于"仅充电/U盘"模式换一根支持数据传输的线 → 手机上允许 USB 调试 → 装厂商驱动 → 切换为"传输文件"模式真机
真机上图片是空白，浏览器正常图片不在 static/ 目录，没被编译进包把图片移到 static/，引用写 /static/xxx.png；网络图与 base64 也可用真机
iOS 真机无法运行iOS 真机早已不支持标准基座申请证书制作自定义基座，或用 Mac 上的 iOS 模拟器；Windows 连接 iPhone 还需安装 iTunes 并信任电脑真机
运行到小程序打不开没安装对应开发者工具，或未配置工具路径 / 服务端口安装微信开发者工具并在 HBuilderX 设置里配置路径；运行时注意底部状态栏选择的平台真机
在真机上很卡，但浏览器流畅开发期跑的是 debug 基座测性能必须打 release 正式包；debug 模式的耗时不能当结论真机
改了代码真机没更新差量热刷失败或基座缓存重新点运行；仍无效就在手机上删除基座应用后重新安装运行真机
图片被压扁 / 拉长变形mode 默认是 scaleToFill（拉伸填满）头像与封面用 aspectFill，需要完整显示用 aspectFit，宽度自适应用 widthFix界面
图片两侧 / 上下出现留白用了 aspectFit（保持比例完整显示）想要铺满就换 aspectFill；想让高度自适应就换 widthFix界面
图片把布局撑开了image 不写宽高时用默认尺寸 320 × 240务必显式设置 width / height，或用 widthFix界面
scroll-view 完全滚不动内容高度没有超过 scroll-view 自身高度（没设高度时它和内容一样高）给 scroll-view 设固定 height，或用 flex: 1 撑满剩余空间界面
上拉加载一次触发很多遍没有加"加载中"锁，滚动到底反复触发用 loading 标记在最前面 return；同时用 noMore 标记停止请求界面
下拉刷新一直转圈停不下来refresher-triggered 没有设回 false刷新完成后（成功或失败都要）把 refresher-triggered 置为 false界面
文字被容器裁掉 / 省略号不出现没有宽度，或缺少 text-overflow 与 white-space单行：确定宽度 + text-overflow: ellipsis + white-space: nowrap；多行：用 text 的 :max-lines界面
底部按钮被手机手势条挡住没有适配安全区底栏补 padding-bottom: var(--uni-safe-area-inset-bottom)（HBuilderX 4.52+），不要用已废弃的 --window-bottom界面
几百条数据滚动明显卡顿一次性渲染了大量节点长列表改用 list-view + list-item，并补全 :key；图片先定尺寸界面
浏览器好看，真机排版错乱用了 Web 支持的写法（标签选择器、伪元素、float 等）逐条对照附录 A「危险写法清单」排查界面
没有匹配的症状，换个关键词试试（例如 白屏、static、key、连不上）。

B.3

四个够用的调试手法

10 分钟 · 动手照抄

不需要复杂工具，把这四招用熟，能解决你 95% 的问题。

调试代码片段：打印、弹窗、兜底、看结构 
<script setup>
  // ① 打印：最常用。位置在 HBuilderX 底部「控制台」，真机运行也会打印
  const onLoad = () => {
    console.log('页面加载了')
  }

  // ② 弹窗：不依赖电脑，直接在手机屏幕上看到结果（真机调试神器）
  const check = () => {
    uni.showModal({ 'title': '调试', 'content': '走到了这一步', 'showCancel': false })
  }

  // ③ 兜底：把可疑代码包起来，先保证程序不崩，同时把错误打出来
  const safeParse = (text: string) => {
    try {
      return JSON.parse(text)
    } catch (e) {
      console.log('解析失败：', e)
      return null
    }
  }

  // ④ 看结构：拿到接口数据先原样打印，确认字段名与层级再写渲染代码
  const showShape = (data: any) => {
    console.log('数据结构：', JSON.stringify(data))
  }
</script>
手法用来回答什么问题什么时候用
console.log 定位法"这段代码到底有没有执行到？变量此刻是什么值？"逻辑不对、数据不对时，在关键分支前后各打一条
uni.showModal 弹窗法"真机上这一步的结果是什么？"手机不方便连电脑看日志时
注释二分法"问题出在哪一半代码里？"白屏、报错、卡死，且日志指向不明时
最简复现法"是环境问题还是我的代码问题？"怀疑工程本身有问题时：新建一个空页面只放一行文字，能跑说明环境没问题
B.4

排错记录模板 & 上交前自查

养成习惯

把每次解决的问题记下来，一学期后你就有了自己的"专属排错手册"——这比任何教程都有用， 也是面试时"你解决过什么难题"的真实素材。

排错记录（复制到自己的笔记里） 
【日期】2026-10-11
【现象】真机上课程封面图一直空白，浏览器里能正常显示
【定位过程】
  1. 控制台无报错 → 排除运行期错误
  2. 换了一张网络图能显示 → 说明 image 组件本身没问题
  3. 怀疑路径 → 查看官方文档，确认只有 static 目录会被编译进包
【原因】图片放在 pages/demo/img/ 下，没有被编译打包
【解决】移到 static/，引用改为 /static/cover.png
【记住的一句话】App 端静态资源只认 static 目录

✅ 提交作业 / 提问前自查 0 / 8 已完成

点一下即可打勾，进度保存在浏览器里。老师最怕看到"跑不起来"这三个字外加一张截图。

控制台有没有红字？第一条报错是什么？
把第一条报错的完整文字复制下来，而不是只截半张图
这个问题在浏览器端能复现吗？（能 → 逻辑问题；不能 → 跨端差异）
两端都测一遍，这个信息能省掉一半排查时间
用注释法确认过问题出在哪一半代码里吗？
把范围缩到 10 行以内，问题基本就自己暴露了
对照过附录 A 的"危险写法清单"吗？（gap / float / 标签选择器 / 伪元素 / 全局 class）
"浏览器正常真机不对"的问题，八成在这里
新页面注册到 pages.json 了吗？路径有没有写后缀？
"页面打不开"最常见的原因
静态资源（图片、字体）都放在 static/ 里了吗？
真机不显示图片的第一嫌疑
把问题代码放到一个空页面里，还能复现吗？
能复现 → 问题在你的代码；不能 → 可能是工程或环境问题
提问时准备好三样东西：报错原文、最小复现代码、已尝试过的办法
这样提问，老师或同学才帮得上你（也是职场上的基本素养）
