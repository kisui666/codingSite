2.1

flex 布局地基：容器、主轴、交叉轴

20 分钟 · 讲授 + 演练

在 Web 里你可以用 block、inline-block、float、grid、flex 混着排版；在 uni-app x 里只有一件事要做： 用 flex 把界面拆成"一层套一层"的容器。好消息是 flex 概念极少，坏消息是大多数人只记住了 "横排要写 row"，却没弄清主轴和交叉轴会随方向翻转。

概念是什么谁来控制方向怎么变
容器 一个 view，它内部的子元素按 flex 规则排列 flex-direction uvue 默认 column（竖向），Web 默认 row
主轴 排列方向那条轴 justify-content column 时主轴是竖的；row 时主轴是横的。uvue 默认 flex-start（从起点排）
交叉轴 与主轴垂直的那条轴 align-items 跟着主轴翻转。uvue 默认 stretch（子元素在交叉轴方向被拉伸填满，这也是子元素"自己变高/变宽"的原因）
剩余空间 容器没被占满的部分 flex: 1 / flex-grow 想让某块"撑满剩下的地方"就给它 flex: 1
!
最容易记混的一点：

justify-content / align-items 控制的是主轴 / 交叉轴，不是"横 / 竖"。 同样是 justify-content: center：在默认竖向容器里它是上下居中， 在 flex-direction: row 的容器里它是左右居中。 记不住就问自己："现在主轴朝哪？"

六个套路，覆盖 80% 的移动端界面

下面的演练区把六个高频套路做成了可切换的示例。建议这样学： 先看效果、猜代码，再翻到代码标签核对；每个套路都顺手在脑子里过一遍"主轴是哪条"。

套路速记表

想要的效果关键写法典型场景
上下排列什么都不写（默认 column）卡片内的信息行
左右排列 + 居中flex-direction: row; justify-content: center; align-items: center;按钮行、工具栏

ⓘ
间距怎么做？没有 gap。

App 端的 ucss 不支持 gap / row-gap / column-gap （官方 CSS 属性清单里没有它们）。元素之间的间距用 margin 实现： 横排用左右 margin，竖排用上下 margin；网格布局则给"格子"加 padding。 box-sizing 默认是 border-box，所以 padding 包含在宽度里，不会把格子撑破。

💡
底部固定栏与安全区（刘海屏）：

布局上优先用 "内容区 flex: 1 + 底栏固定高度" 的方式把底栏挤到底部； 确实需要浮在最上层时可以用 position: fixed。 注意全面屏手机底部有手势条，底栏要补上安全区距离—— 用官方 CSS 变量（HBuilderX 4.52+）：padding-bottom: var(--uni-safe-area-inset-bottom)。 旧的 --window-top / --window-bottom 已废弃，不要再照抄老教程； 另外不要用 calc() 去组合这个变量（官方示例注明 App 端暂不支持 calc）， 需要额外留白就给内部按钮加 margin。

2.2

尺寸与适配：px 优先，rpx 用在对的地方

20 分钟 · 讲授 + 计算实操

"移动端要用 rpx"是流传最广的半句话。官方现在的口径是： App 端的 px 就是逻辑像素（会按屏幕密度自动换算，不是物理像素）， 所以推荐尽量使用 px；rpx 的价值在于"严格按设计稿等比缩放"， 在平板、折叠屏、横屏、PC 宽屏上反而会偏大。性能上大致是 px > rpx > 百分比。

单位含义什么时候用注意
px App 端的逻辑像素，各端表现一致 默认首选：字号、圆角、边框、间距、图标尺寸 语义清晰、性能最好
rpx 以 750px 为基准：750rpx = 屏幕宽度 设计稿按 750px 宽出图、且要求"大屏小屏等比缩放"的元素 平板 / 折叠屏 / 横屏会偏大；不适合字号
百分比 % 相对父容器的比例 网格格子、进度条、宽度自适应 高度用百分比时父容器必须有确定高度
flex: 1 占满剩余空间（不是单位，是属性） 内容区撑满、等分列、页面根节点 页面根节点写 flex: 1 才能占满整屏

拿到设计稿时先问两件事：设计稿宽度是多少？（750 还是 375 / 390） 这个元素要不要等比缩放？用下面的小工具试几个数字，比背公式快得多。

换算公式（记一次就够）：

rpx 值 = 标注值 × (750 ÷ 设计稿宽度)； 元素在设备上的实际宽度 = rpx 值 ÷ 750 × 设备宽度。 设计稿就是 750px 宽时，标注多少就写多少 rpx，不用算。

2.3

view 与 text：容器与文字的职责分工

20 分钟 · 讲授 + 演练

view 是容器（相当于 div），text 是文字（相当于 span / p）。 这两个组件的属性都不多，但"文字必须放 text、样式不继承"这条规则决定了你 90% 的代码结构。

组件常用属性说明与坑
view hover-class（默认 none）
hover-start-time（默认 50ms）
hover-stay-time（默认 400ms）
hover-stop-propagation		 想给 view 加点击反馈，必须显式指定 hover-class—— 默认值是 none，也就是"什么都不发生"。App 端不支持 :active 伪类，只能用这个属性。
text user-select（默认 false）
max-lines（默认不限）
hover-class、flatten		 文字相关样式都要写在 text 或其 class 上； 子组件只能是 text，且子 text 不继承父样式， 连 margin / padding / width 都不生效。 蒸汽模式下 space 与 decode 属性已废弃（space 改用 CSS 的 white-space）。

三个真实场景：点击态、省略号、可复制文字

下面三个示例都对应真实需求：列表项要有按下反馈、标题太长要显示省略号、 订单号要能被长按复制。点标签逐个看。

pages/demo/text.uvue —— 省略号与可选中 
<template>
  <view class="page">
    <!-- 单行省略：宽度 + text-overflow + white-space -->
    <text class="one-line">这是一段很长的课程标题，超出容器宽度后应该显示省略号而不是换行</text>

    <!-- 多行省略：max-lines 是组件属性（不是 CSS 的 lines） -->
    <text class="multi-line" :max-lines="2">
      移动端界面的排版绝大多数都可以用 flex 完成，
      但新手最容易在间距、单位和滚动容器这三处翻车。
    </text>

    <!-- 可选中 / 可复制：user-select（selectable 已被它取代） -->
    <text class="code-text" user-select>订单号：20261011XY9527</text>
  </view>
</template>

ⓘ
为什么单行省略不用写 overflow: hidden？

因为 ucss 里 overflow 的默认值就是 hidden（W3C 是 visible）。 但 width（或父容器限定的宽度）必须存在，否则文本不知道自己该在哪儿截断。 另外 CSS 的 lines 属性已废弃，多行省略用 text 组件的 :max-lines="2"。

2.4

image：图片显示、裁切与路径规则

20 分钟 · 讲授 + 演练

image 组件的核心是 mode：它决定图片在给定宽高里怎么"塞"进去。 默认值是 scaleToFill（强行拉伸填满，会变形），所以"图片被压扁了"是新手最常见的问题之一。

mode行为用在哪
scaleToFill（默认）不保持比例，拉伸填满整个区域背景图（且比例恰好合适时）
aspectFit保持比例完整显示，可能留白商品图、需要看清全貌的图
aspectFill保持比例填满，超出部分裁掉头像、卡片封面（最常用）
widthFix宽度固定，高度按比例自适应文章配图、宽度自适应的高度不定图
heightFix高度固定，宽度按比例自适应高度对齐的图标列
位置类top bottom center left right 及四个角（如 top left）保持原尺寸、把图对齐到指定位置（不缩放）
✕
图片"浏览器里能看、真机上是空白"，99% 是路径问题：

编译器只会把 static/ 目录下的静态资源打进 App 包， 所以 image 的 src 要写成 /static/xxx.png（项目或 uni_modules 下的 static 都行）。 把图片放在 pages/、assets/ 之类目录里，浏览器预览正常，真机却不显示。 此外也支持网络图片（http/https）、本地文件路径（file:///）和 base64 的 Data URL。

pages/demo/image.uvue —— 头像 + 封面 + 加载失败兜底 
<template>
  <view class="page">
    <view class="row">
      <!-- 头像：正方形 + aspectFill 裁切，永远不会变形 -->
      <image class="avatar" src="/static/avatar.png" mode="aspectFill"></image>
      <view class="profile">
        <text class="name">汽水同学</text>
        <text class="muted">计算机科学与技术 · 2024 级</text>
      </view>
    </view>

    <!-- 封面图：宽度撑满、高度自适应 -->
    <image class="cover" src="/static/cover.png" mode="widthFix" @error="onImgError"></image>
  </view>
</template>

<script setup>
  const onImgError = () => {
    // @error 的 detail 里有 errMsg，方便定位是路径错了还是网络问题
    uni.showToast({ 'title': '图片加载失败', 'icon': 'none' })
  }
</script>

<style>
  .page { flex: 1; padding: 16px; background-color: #FFFFFF; }
  .row { flex-direction: row; align-items: center; margin-bottom: 20px; }
  .avatar { width: 64px; height: 64px; border-radius: 32px; margin-right: 12px; }
  .profile { flex: 1; }
  .name { font-size: 17px; font-weight: bold; }
  .muted { font-size: 13px; color: #5A6B8C; }
  .cover { width: 100%; border-radius: 12px; }
</style>
💡
两个细节：

① image 默认尺寸是 320px × 240px，所以一定要显式写宽高，否则布局会莫名其妙被撑开； ② image 不能嵌套子组件，需要在图上叠文字，请用外层 view + position 实现。

2.5

scroll-view：滚动、上拉加载、下拉刷新

25 分钟 · 讲授 + 代码实操

页面本身默认就能滚动，那什么时候需要 scroll-view？ 当你要局部滚动时：比如上半屏固定、下半屏是列表；或者横向滚动的标签栏。 它的第一原则是必须有一个确定的高度——这也是"设了 scroll-view 却滚不动"的唯一原因。

!
滚动的必要条件（官方原文的意思）：

内容高度必须大于 scroll-view 自身高度才能滚动。 如果不给 scroll-view 设高度，它的高度默认与子内容一样高，那就永远滚不起来。 两种正确做法：给它固定 height，或者给它 flex: 1 撑满剩余空间。

关注点写法说明
滚动方向direction="vertical"（默认）/ horizontal / none / all新版用 direction，不再用 scroll-x / scroll-y
滚动监听@scroll / @scrollend / @scrolltolower / @scrolltoupper上拉加载用 @scrolltolower，触顶用 @scrolltoupper
下拉刷新refresher-enabled + refresher-triggered + @refresherrefreshrefresher-triggered 是双向的：刷完要手动设回 false，否则转圈不停
滚到指定位置scroll-top / scroll-left / scroll-into-viewscroll-into-view 传子元素的 id，且 id 不能以数字开头
平滑滚动scroll-with-animation配合 scroll-top 做"回到顶部"

完整案例：上拉加载 + 下拉刷新

这是移动端列表页的标准骨架，请务必自己敲一遍（第 8 章接真实接口时会直接复用）。

pages/demo/list.uvue 
<template>
  <view class="page">
    <!-- flex: 1 让 scroll-view 撑满剩余空间，这样内容超出才能滚动 -->
    <scroll-view
      class="list"
      direction="vertical"
      :refresher-enabled="true"
      :refresher-triggered="refreshing"
      @refresherrefresh="onRefresh"
      @scrolltolower="loadMore">

      <view class="item" v-for="item in list" :key="item.id">
        <text class="title">{{ item.title }}</text>
        <text class="muted">{{ item.time }}</text>
      </view>

      <!-- 加载状态提示：三态都要有，否则用户不知道发生了什么 -->
      <view class="footer-tip">
        <text class="muted">{{ loading ? '加载中…' : (noMore ? '没有更多了' : '上拉加载更多') }}</text>
      </view>
    </scroll-view>
  </view>
</template>
<script setup>
  type Notice = { id: number, title: string, time: string }

  const list = ref<Notice[]>([])
  const page = ref(1)
  const loading = ref(false)
  const noMore = ref(false)
  const refreshing = ref(false)

  // 模拟一次网络请求（第 8 章会换成 uni.request）
  const fetchPage = (p: number): Notice[] => {
    const result: Notice[] = []
    for (let i = 0; i < 10; i++) {
      const id = (p - 1) * 10 + i + 1
      result.push({ 'id': id, 'title': '校园通知 ' + id, 'time': '2026-10-11' })
    }
    return result
  }

  const loadMore = () => {
    if (loading.value || noMore.value) return       // 防止重复触发
    loading.value = true
    setTimeout(() => {
      const rows = fetchPage(page.value)
      list.value = list.value.concat(rows)
      page.value = page.value + 1
      loading.value = false
      if (page.value > 4) noMore.value = true        // 演示用：4 页之后没有更多
    }, 400)
  }

  const onRefresh = () => {
    refreshing.value = true
    setTimeout(() => {
      page.value = 1
      noMore.value = false
      list.value = fetchPage(1)
      refreshing.value = false                      // 必须设回 false，否则转圈不停
      uni.showToast({ 'title': '刷新完成', 'icon': 'none' })
    }, 600)
  }

  onLoad(() => { loadMore() })
</script>
<style>
  .page { flex: 1; background-color: #F5F8FF; }
  /* 关键：flex: 1 撑满剩余空间，scroll-view 才有确定高度 */
  .list { flex: 1; }
  .item {
    background-color: #FFFFFF;
    border-radius: 12px;
    padding: 16px;
    margin: 8px 12px;
  }
  .title { font-size: 16px; font-weight: bold; margin-bottom: 4px; }
  .muted { font-size: 12px; color: #5A6B8C; }
  .footer-tip { padding: 16px; justify-content: center; align-items: center; }
</style>
💡
横向滚动（标签栏 / 图片墙）：

把 direction 改成 horizontal，子元素用 flex-direction: row 排列， 并给 scroll-view 一个固定高度（横向滚动时高度不会自动撑开）。 标签之间同样用 margin 制造间距，别用 gap。

2.6

v-for 列表渲染与 :key 的真正作用

20 分钟 · 讲授 + 演练

列表是移动端出现频率最高的结构：通知、课程、商品、聊天记录。写法就一行 v-for="item in list" :key="item.id"，但 :key 写错会带来"看起来随机"的诡异 bug。

v-for 写法要点 
<!-- 基础写法：item 是当前项，index 是下标 -->
<view v-for="(item, index) in list" :key="item.id">
  <text>{{ index + 1 }}. {{ item.name }}</text>
</view>

<!-- 只取一项时 index 可以省略 -->
<view v-for="item in list" :key="item.id">
  <text>{{ item.name }}</text>
</view>

<!-- :key 的取值：number / string / symbol，必须唯一且稳定 -->
<!-- 推荐用后端返回的 id；没有 id 时用"业务上不会重复的字段" -->

<!-- 反例：用 index 当 key（删除/排序后组件会被复用到错误的项上） -->
<view v-for="(item, index) in list" :key="index">
  <text>{{ item.name }}</text>
</view>
ⓘ
官方在这件事上有多认真：

蒸汽模式明确规定：list-item 的 v-for 必须带 :key， 否则组件无法复用（也就是说性能会明显变差）。 另外要注意：v-if 与 v-for 尽量别写在同一层——先用计算属性把数据过滤好，再渲染列表，逻辑更清晰、性能也更好。

2.7

长列表与性能：什么时候该换组件

10 分钟 · 讲授

10 条数据和 1000 条数据，处理方式不应该一样。官方给出的分工很明确： 长列表场景用 list-view + list-item， 其他场景用 scroll-view。原因是 App 端基于复用回收的 list 才能实现长列表的渲染资源复用—— 滚动时只渲染屏幕附近的项，而不是把上千个节点全建出来。

场景推荐组件原因
几十条以内的通知 / 设置项scroll-view够用，写法简单
成百上千条的动态流、聊天记录list-view + list-item支持复用回收，内存与流畅度可控；list-item 的 v-for 必须带 :key
横向标签栏、横向图片墙scroll-view direction="horizontal"局部横向滚动
整页内容不多直接用页面滚动不必套 scroll-view

不用新组件也能立刻提速的 5 个习惯

  • 图片先定尺寸：给 image 写死宽高（或 widthFix），避免图片加载完成后整页重排；
  • 减少无意义的嵌套：三层 view 能做完的，不要写六层；每层都要参与布局计算；
  • 循环里不做重计算：把过滤、排序放到 computed 里，而不是在模板里每次都算；
  • 长列表别一次性全量赋值：分页追加（concat）比整表替换更省；
  • 性能要用正式包测：开发期是真机 debug 基座，跑出来的耗时不能当结论；测性能请打 release 包。
✓
本节的验收标准：

当你的列表滚动明显掉帧时，先看是不是"一次性渲染了几百个节点"； 是的话换 list-view，并把 :key 补全。

📌 今天你学到的，浓缩成 6 句话

uvue 里布局只有 flex 一条路：默认竖向，主轴与交叉轴随方向翻转； 间距一律用 margin / padding，没有 gap； 尺寸优先用 px（逻辑像素），需要按 750px 设计稿等比缩放时才用 rpx； view 是容器、text 是文字，文字样式必须写在 text 上， view 的点击反馈要用 hover-class（默认 none）； image 一定要写宽高、按场景选 mode，图片只能放 static/； scroll-view 必须有确定高度才能滚动，长列表改用 list-view + list-item， v-for 的 :key 要用唯一且稳定的值。

flex 默认竖向 主轴 / 交叉轴 justify-content align-items flex: 1 撑满 flex-wrap 网格 用 margin 代替 gap px 优先 / rpx 等比 hover-class max-lines 省略号 image mode /static 路径 scroll-view 高度 下拉刷新 上拉加载 v-for / :key list-view 长列表 安全区适配
