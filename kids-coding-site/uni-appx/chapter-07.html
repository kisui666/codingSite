页面路由与生命周期：把多个页面组成一个 App

单页面练熟了，接下来是"页面之间"的问题：怎么跳、怎么传参数、返回时怎么把结果带回来， 以及哪段逻辑该写在哪个生命周期里。 这一章是"作业级项目"和"能用的 App"之间的分水岭—— 大多数人卡住不是因为不会跳转，而是因为把刷新逻辑放错了钩子，导致数据看起来"时好时坏"。

7.1

页面栈：理解"跳转"的本质

20 分钟 · 讲授 + 演练

把页面想象成一叠卡片：当前屏幕上是栈顶那张。 "跳转"其实就是对这叠卡片的不同操作——理解了这一点，五种 API 就不用背了。

API对页面栈做什么典型场景还能返回吗
uni.navigateTo 入栈：新页面压在上面，旧页面还在 列表 → 详情、设置 → 子设置 能，返回后原样恢复
uni.redirectTo 替换栈顶：关闭当前页再开新页 登录页 → 主页（不希望用户退回到登录页） 不能退回上一页
uni.reLaunch 清空并重开：关掉所有页面，只留新页 退出登录、切换账号、从异常页回到起点 不能
uni.switchTab 切到底部导航页（tabBar 页面） 底部导航栏之间切换 由 tabBar 决定
uni.navigateBack 出栈：关闭当前页，回到上一页 详情页返回、表单取消 —
✕
官方明确限制：navigateTo 的 url 不能是 tabBar 页面。

也就是说：如果你的页面出现在底部导航里，只能用 uni.switchTab 跳过去。 用 navigateTo 会直接失败——这也是新手最常见的"跳转没反应"的原因之一。 另外 reLaunch 到 tabBar 页面时不能带参数。

五种跳转的写法（含带动画的跳转） 
<script setup>
  // ① 入栈：最常见的"打开详情"
  const goDetail = (id: number) => {
    uni.navigateTo({
      'url': '/pages/detail/detail?id=' + id,
      'animationType': 'slide-in-right',      // 可选：入场动画
      'animationDuration': 200
    })
  }

  // ② 替换当前页：登录成功后不希望退回登录页
  const goHome = () => {
    uni.redirectTo({ 'url': '/pages/home/home' })
  }

  // ③ 清空页面栈重开：退出登录 / 切换账号
  const logout = () => {
    uni.reLaunch({ 'url': '/pages/login/login' })
  }

  // ④ 切换底部导航页（注意：不是 navigateTo）
  const goMine = () => {
    uni.switchTab({ 'url': '/pages/mine/mine' })
  }

  // ⑤ 返回上一页（最常见的是直接调用，不带参数）
  const goBack = () => {
    uni.navigateBack()
  }
</script>
ⓘ
跳转失败怎么排查？

官方说明失败回调里带 errCode、errSubject、errMsg， 其中 errCode 为 4 表示框架内部异常。 实践中最常见的三种失败原因：① 目标页面没在 pages.json 注册（路径写错或没登记）； ② 用 navigateTo 跳了 tabBar 页面；③ 路径忘了以 / 开头。 建议在开发期给跳转都加上 fail 回调打日志。

7.2

页面传参：url 拼接 + onLoad 取值

20 分钟 · 讲授 + 演练

页面之间的参数走 url 查询字符串：发起的页面把参数拼在 url 里，接收的页面在 onLoad 的回调参数里取出来。关键提醒：取出来的值都是字符串， 数字要自己转换——这是最常被忽略的一点。

传参的两个页面（官方示例形态） 
<script setup>
  const posts = ref<Post[]>([])

  const openPost = (item: Post) => {
    // 参数拼在 url 后面；多个参数用 & 连接
    uni.navigateTo({
      'url': '/pages/detail/detail?post_id=' + item.id + '&title=' + item.title
    })
  }
</script>
<script setup>
  const postId = ref<string>('')
  const title = ref<string>('')

  // onLoad 的参数类型是 OnLoadOptions（也可以省略类型标注）
  // 它只会执行一次：页面第一次创建时
  onLoad((options: OnLoadOptions) => {
    // 取值用方括号，并提供兜底，避免 undefined 直接参与渲染
    postId.value = options['post_id'] ?? ''
    title.value = options['title'] ?? ''
    console.log('收到参数：', postId.value, title.value)
  })
</script>
// 坑 ①：取出来的都是字符串
//   ?id=12  →  options['id'] 是 '12'，不是 12
//   需要数字就自己转：const id = Number(options['id'] ?? '0')

// 坑 ②：参数里带中文、空格、& 等字符时，建议先编码
uni.navigateTo({
  'url': '/pages/detail/detail?title=' + encodeURIComponent('数据结构 & 算法')
})
// 接收页再解码：decodeURIComponent(options['title'] ?? '')

// 坑 ③：不要用 url 传"大对象"
//   参数只适合传 id、简单标志位；
//   复杂数据请用全局状态（第 9 章）或本地存储传递
💡
一条能省很多事的约定：

页面之间只传 id，不传整条数据。 详情页拿到 id 之后，自己去取数据（或从全局状态里查）。 这样做的好处是：详情页可以被"消息推送""分享链接""二维码"等任何入口直接打开—— 如果它依赖上一页传过来的整条数据，这些入口就全用不了。

7.3

返回时把数据带回去：两种官方方案

20 分钟 · 讲授

一个高频需求：用户在"新增页面"填完表单，点保存后返回列表，列表要出现这条新数据。 有三条路，各有适用场景：

方案怎么做适合场景
① 在 onPageShow 里重新拉数据（最推荐） 列表页每次显示都重新请求/读取一次数据 数据量不大、接口便宜；最稳，不依赖上一页做了什么
② navigateTo 的 events 选项 官方提供的页面间通信接口：跳转时带上事件回调，目标页触发后回传数据 需要精确回传某个结果（例如"选择了一个城市"）
③ 事件总线 uni.$emit / uni.$on 全局事件：一端 $emit，另一端 $on 接收 跨多个页面的通知（例如"登录状态变了"）
方案 ①：用 onPageShow 保证"回来就是最新数据" 
<script setup>
  const posts = ref<Post[]>([])

  const load = () => {
    // 真实项目里这里是 uni.request（第 8 章）
    posts.value = readFromStore()
  }

  onLoad(() => {
    console.log('页面创建，只执行一次')
    load()
  })

  // 关键：从"新增页/详情页"返回时也会执行，
  // 所以列表总能拿到最新数据，不需要上一页专门回传
  onPageShow(() => {
    console.log('页面每次显示都会执行')
    load()
  })
</script>
方案 ②：events 精确回传 / 方案 ③：事件总线 
// 发起页：跳转时把"收到结果后做什么"一起带过去
uni.navigateTo({
  'url': '/pages/city/city',
  'events': {
    // 目标页通过 eventChannel 触发这个事件
    'citySelected': (data: string) => {
      city.value = data
    }
  }
})

// 说明：events 是官方给出的"页面间通信接口"。
// 目标页如何取出 eventChannel 并触发事件，请以官方 navigator 文档与示例为准。
// 页面 A：监听事件（一般放在 onLoad 里注册）
const onLoginChanged = (isLogin: boolean) => {
  console.log('登录状态变了：', isLogin)
}

onLoad(() => {
  // uni.$on 返回监听器的 id（4.31+）
  uni.$on('loginChanged', onLoginChanged)
})

// 关键：页面卸载时一定要取消监听，否则会重复触发
onUnload(() => {
  uni.$off('loginChanged', onLoginChanged)
})

// 页面 B：发出事件
uni.$emit('loginChanged', true)

// 官方注意事项：
// ① eventName 不要以 uni 开头（避免与内置事件冲突）
// ② 参数只支持基础类型、string、Array、UTSJSONObject 这类可序列化的数据
// ③ 还有 $once（只监听一次）与 $off（取消监听）
!
事件总线最容易犯的两个错：

① 只 $on 不 $off——页面被打开多次后会注册多个监听， 一次 $emit 触发 N 次回调，表现为"日志打印了好几遍""数据被加了多次"； ② 用事件总线传大对象——官方说明它只支持可序列化的基础数据， 复杂数据请走全局状态。

7.4

页面生命周期：哪段逻辑该住在哪里

25 分钟 · 讲授 + 演练

组合式 API 下，页面生命周期直接调用即可，不需要 import（和 ref 一样由编译器自动引入）。 官方给出的完整名单如下——不用全部记住，但要知道每一类该放什么。

钩子触发时机该放什么
onLoad页面第一次创建时（只执行一次）接收参数、做一次性的初始化
onReady页面首次渲染完成（只执行一次）需要操作界面元素的逻辑（此时 DOM 才建好）
onPageShow每次页面显示（从别的页面回来也会触发）需要"回来就刷新"的加载逻辑
onPageHide页面隐藏（跳到别的页面、切后台）暂停轮询、暂停动画、记录离开时间
onUnload页面被关闭销毁清理：定时器、事件监听、未完成的请求
onPullDownRefresh下拉刷新被触发重新拉数据，并在结束时停止刷新动画
onReachBottom滚动到底部上拉加载下一页
onPageScroll页面滚动（频率高）只做极轻的事（例如"显示回到顶部按钮"），别在这里发请求
onBackPress用户按返回（仅 App 平台）拦截返回："还没保存，确定离开吗？"
onTabItemTap点击底部导航项同一个 tab 被再次点击时刷新
onResize窗口尺寸变化（横竖屏、折叠屏）重新计算布局
onBackPress 之外的分享类（onShareAppMessage 等）小程序端分享相关课程项目里较少用到，了解即可
✕
最经典的一个错误：把"刷新"写在 onLoad 里。

onLoad 只在页面第一次创建时执行一次，所以"列表 → 详情 → 返回列表"时它不会再跑， 用户就会看到旧数据。这不是 Bug，是把刷新逻辑放错了地方。 记住这条判断规则：要"每次看到都是最新"就放 onPageShow； 只做一次的初始化才放 onLoad。

💡
关于组件里的生命周期：

组件不能用 onLoad / onPageShow 这类页面生命周期（第 6 章讲过）。 但组合式 API 写的组件可以监听它所在页面的页面生命周期—— 需要在组件内部响应"页面显示"时，这一点很有用。

7.5

下拉刷新与触底加载：移动端的两个肌肉记忆

15 分钟 · 讲授

这两种交互是移动端用户的肌肉记忆：到了屏幕顶部"往下拽"，到了底部"继续往上推"。 它们的实现分两步：先在 pages.json 里开启，再在页面里实现钩子。

第一步：pages.json 开启下拉刷新与配置触底距离 
{
  "pages": [
    {
      "path": "pages/list/list",
      "style": {
        "navigationBarTitleText": "通知列表",
        "enablePullDownRefresh": true,
        "onReachBottomDistance": 80,
        "backgroundColor": "#F5F8FF",
        "backgroundTextStyle": "dark"
      }
    }
  ]
}
第二步：页面里实现两个钩子（含"上拉加载"的三态处理） 
<script setup>
  const list = ref<Notice[]>([])
  const page = ref<number>(1)
  const loading = ref(false)
  const noMore = ref(false)

  const fetchPage = (p: number): Notice[] => {
    const rows: Notice[] = []
    for (let i = 0; i < 10; i++) {
      const id = (p - 1) * 10 + i + 1
      rows.push({ 'id': id, 'title': '通知 ' + id })
    }
    return rows
  }

  // 下拉刷新：用户往下拽时触发
  onPullDownRefresh(() => {
    page.value = 1
    noMore.value = false
    list.value = fetchPage(1)
    // 关键：一定要停止刷新动画，否则会一直转圈
    uni.stopPullDownRefresh()
  })

  // 触底加载：滚动到底部（默认距底 50px，可在 pages.json 里调 onReachBottomDistance）
  onReachBottom(() => {
    if (loading.value || noMore.value) return   // 双重锁，防止重复触发
    loading.value = true
    setTimeout(() => {
      const next = page.value + 1
      list.value = list.value.concat(fetchPage(next))
      page.value = next
      loading.value = false
      if (next >= 3) noMore.value = true
    }, 300)
  })

  onLoad(() => {
    list.value = fetchPage(1)
  })
</script>
!
两个必查项：

① 下拉刷新结束后必须调用 uni.stopPullDownRefresh()， 否则动画一直转（第 2 章 scroll-view 的 refresher-triggered 是同一个道理）； ② 触底加载要加"加载中"锁——滚动到底部会连续触发多次，不加锁就会出现重复请求与重复数据。

7.6

tabBar：给 App 装上底部导航

20 分钟 · 讲授 + 动手

tabBar 完全靠配置完成，不需要写页面代码。配置写在 pages.json 的 tabBar 节点里：

pages.json —— 两个 tab 的完整配置 
{
  "pages": [
    { "path": "pages/index/index", "style": { "navigationBarTitleText": "首页" } },
    { "path": "pages/mine/mine", "style": { "navigationBarTitleText": "我的" } }
  ],
  "tabBar": {
    "color": "#7A7E83",
    "selectedColor": "#2F6BFF",
    "backgroundColor": "#FFFFFF",
    "borderStyle": "black",
    "list": [
      {
        "pagePath": "pages/index/index",
        "iconPath": "static/tab-home.png",
        "selectedIconPath": "static/tab-home-active.png",
        "text": "首页"
      },
      {
        "pagePath": "pages/mine/mine",
        "iconPath": "static/tab-mine.png",
        "selectedIconPath": "static/tab-mine-active.png",
        "text": "我的"
      }
    ]
  }
}
要点说明
图标路径图标要放在 static/ 下（第 1 章讲过：其他目录不会被编译打包）
每个 tab 需要两张图普通态 iconPath 与选中态 selectedIconPath
tab 页面必须在 pages 里注册tabBar 只负责"显示"，页面本身仍要注册
跳转方式只能 switchTab；navigateTo 会失败
尺寸官方说明：导航栏高 44px、tabBar 高 50px（不含底部安全区）
不支持 midbutton官方明确：uni-app x 不再支持老版 uni-app 的 midbutton 中间凸起按钮；需要这类效果请用扩展组件（如 uni-ui x 的 tab-bar）
运行时控制 tabBar：红点、角标、隐藏显示 
<script setup>
  // 给某个 tab 加数字角标（例如"我的"上有 3 条新消息）
  const setBadge = () => {
    uni.setTabBarBadge({ 'index': 1, 'text': '3' })
  }

  // 去掉角标
  const clearBadge = () => {
    uni.removeTabBarBadge({ 'index': 1 })
  }

  // 只显示一个小红点
  const showDot = () => {
    uni.showTabBarRedDot({ 'index': 1 })
  }

  // 动态显示/隐藏整个 tabBar（例如全屏看视频时隐藏）
  const hideTabBar = () => {
    uni.hideTabBar()
  }
</script>

<!-- 官方说明这些 API 的失败回调里：
     errCode 100 表示 TabBar 不存在，200 表示参数错误 -->
💡
tabBar 页面的生命周期细节：

点击已经选中的 tab 时，页面不会重新创建，而是触发 onTabItemTap。 所以"再次点击同一个 tab 就刷新列表"这类需求，要写在 onTabItemTap 里， 而不是指望 onLoad 再跑一次。

7.7

导航栏与页面配置：全局与页面的覆盖关系

15 分钟 · 讲授

页面的外观大部分在 pages.json 里配置。规则很简单： globalStyle 管全局，页面自己的 style 覆盖 globalStyle （官方明确：globalStyle 优先级低于页面级 style）。

globalStyle 常用字段 + 页面级覆盖 
{
  "globalStyle": {
    "navigationBarBackgroundColor": "#2F6BFF",
    "navigationBarTextStyle": "white",
    "navigationBarTitleText": "校园助手",
    "backgroundColor": "#F5F8FF",
    "backgroundTextStyle": "dark",
    "onReachBottomDistance": 50
  },
  "pages": [
    {
      "path": "pages/index/index",
      "style": {
        "navigationBarTitleText": "首页"
      }
    },
    {
      "path": "pages/player/player",
      "style": {
        "navigationStyle": "custom",
        "disableScroll": true,
        "navigationBarTextStyle": "black"
      }
    }
  ]
}
字段作用注意
navigationBarTitleText导航栏标题运行时也能用 uni.setNavigationBarTitle 动态改
navigationBarTextStyle导航栏文字颜色只有 black / white 两个值
navigationStyle: "custom"隐藏系统导航栏，自己画画的时候记得处理状态栏高度，否则会被刘海/状态栏压住
backgroundColor / backgroundTextStyle下拉时露出的窗口底色与 loading 样式深色主题下要一起改
enablePullDownRefresh是否开启下拉刷新不开的话 onPullDownRefresh 不会触发
onReachBottomDistance距底部多少 px 触发触底默认 50；长列表可调大一点提前加载
disableScroll禁用页面滚动官方说明：蒸汽模式页面默认可以滚动（HBuilderX 5.12+），需要禁用时才配它
ⓘ
页面级还有一批平台差异字段：

bounces / allowsBounceVertical（iOS 回弹）、 backgroundColorTop / backgroundColorBottom（仅 iOS）、 titleImage、transparentTitle、pageOrientation、hideStatusBar、 animationType / animationDuration（页面切换动画）等。 这些属于"按需查文档"的字段，需要时对照官方 pages.json 文档确认当前版本的支持情况。

✓
本章验收标准：

能做出一个"底部有两个 tab、列表可以下拉刷新和上拉加载、点进详情能返回且返回后数据是最新的"的 多页面 App 骨架——这就是后面第 11、12 章项目的地基。

页面栈是一叠卡片：navigateTo 入栈、redirectTo 替换栈顶、reLaunch 清空重开、switchTab 切底部导航、navigateBack 出栈； navigateTo 不能跳 tabBar 页面，只能 switchTab，且 reLaunch 到 tab 页不能带参数； 传参走 url 查询字符串、在 onLoad 的 options 里取，取出来全是字符串，含特殊字符要先编码； 想把结果带回上一页，首选"在 onPageShow 里重新加载"， 需要精确回传再用 events 或事件总线（$emit/$on，记得 $off）； onLoad 只跑一次、onPageShow 每次显示都跑——"回来要刷新"必须放后者； 下拉刷新要在 pages.json 开启并调用 uni.stopPullDownRefresh()，触底加载用 onReachBottom 并加"加载中"锁。
