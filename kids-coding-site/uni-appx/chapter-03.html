3.1

样式从哪来，谁能影响谁：样式隔离策略 2.0

20 分钟 · 讲授 + 演练

在 uni-app x 里，class 有三个来源，它们的"势力范围"由样式隔离策略决定：

样式来源写在哪默认谁能引用同名时的优先级
全局样式 App.uvue 的 <style> 页面可以引用；组件默认引用不到 页面 > 全局
页面样式 页面 .uvue 的 <style> 只在本页面生效（配置成 app-and-page 的组件才能引用） 页面 > 组件 > 全局
组件样式 组件 .uvue 的 <style> 只在组件内部生效，默认完全隔离 组件 > 全局
✕
新手最常撞的一堵墙：

你在 App.uvue 里辛辛苦苦写了一个 .card 通用样式， 页面里用得好好的，一放进自定义组件就完全没效果。 原因不是你写错了，而是：组件的默认隔离策略是 isolated，组件里根本引用不到全局 class。 这不是 Bug，是设计——为了让组件不被外部样式"污染"。

用 defineOptions 明确"要不要被外部影响"

页面和组件都可以在 <script setup> 里用 defineOptions 声明自己的隔离策略。 取值只有三个，含义如下（页面的默认值是 app，组件的默认值是 isolated）：

取值能引用全局 class能引用页面 class同名合并优先级
isolated
（组件默认）		 不能 不能 不合并，彻底隔离
app
（页面默认）		 能 页面配置时自身即页面（不适用） 页面 > 全局；组件 > 全局
app-and-page
（仅组件可用）		 能 能 页面 > 组件 > 全局
components/InfoCard.uvue —— 显式声明隔离策略 
<template>
  <view class="info-card">
    <text class="title">{{ title }}</text>
    <text class="body">{{ content }}</text>
  </view>
</template>

<script setup>
  // 场景一：组件希望用全局的通用样式（如统一圆角、阴影）
  // defineOptions({ styleIsolation: 'app' })

  // 场景二：组件既想用全局样式，又想被所在页面的样式微调
  defineOptions({ styleIsolation: 'app-and-page' })

  // 场景三（组件默认）：完全隔离，外部影响不进来
  // defineOptions({ styleIsolation: 'isolated' })

  const props = defineProps<{
    title: string,
    content: string
  }>()
</script>

<style>
  .info-card {
    background-color: #FFFFFF;
    border-radius: 12px;
    padding: 16px;
  }
  .title { font-size: 16px; font-weight: bold; margin-bottom: 6px; }
  .body { font-size: 14px; color: #5A6B8C; }
</style>

组件被隔离了，外部还想定制样式怎么办？

隔离之后，组件作者需要提供"合法的口子"。官方给的机制叫 external-class （defineOptions 里注册 externalClasses），思路是： 组件把内部某个子元素的样式开放出来，外部传一个 class 名进来覆盖。 这和很多组件库里 placeholder-class、thumb-class 之类的用法是同一套机制。

组件作者：暴露可定制点 / 组件使用者：传入 class 
<!-- components/UniSwitch.uvue -->
<template>
  <view class="uni-switch">
    <!-- 圆球：把它的样式开放给外部，属性名是 thumbClass -->
    <view class="uni-switch-thumb" :class="thumbClass"></view>
  </view>
</template>

<script setup>
  const props = withDefaults(defineProps<{ thumbClass: string }>(), {
    thumbClass: ''
  })

  defineOptions({
    // 注册扩展 class：数组形式，可以注册多个
    externalClasses: ['thumb-class']
  })
</script>

<style>
  .uni-switch { width: 52px; height: 32px; border-radius: 16px; background-color: #E2E9F7; }
  /* 组件内部不写死颜色，留给外部通过 thumb-class 定制 */
  .uni-switch-thumb { width: 26px; height: 26px; border-radius: 13px; background-color: #FFFFFF; }
</style>
<!-- pages/demo/switch.uvue -->
<template>
  <view class="page">
    <!-- 传入 thumb-class，值是自己定义的 class 名 -->
    <uni-switch thumb-class="red-thumb"></uni-switch>
  </view>
</template>

<style>
  /* 这个 class 在页面里定义，却能作用到组件内部的圆球上 */
  .red-thumb {
    background-color: #FF5C7A;
  }
</style>
!
external-class 的三个硬性注意点：

① externalClasses 必须写成静态字面量数组，不能用变量、表达式或函数返回值动态生成； ② 如果你把 class 定义在全局（App.uvue）里，又想覆盖组件内部同名样式， 因为全局优先级最低，需要给对应 CSS 属性加 !important； ③ 组件作者如果不希望某个样式被改，把它写成组件内部的内联 style 即可 （class 的优先级低于内联 style，除非 class 里用了 !important）。

💡
两条容易忽略的规则：

① 组件根节点的样式仍然可以被"传"进来：单根节点组件，父层在组件上写的 class 与 style 会作用到组件根节点；多根节点组件需要组件内部自己分配这些样式； ② 这套策略是 HBuilderX 5.0 起全平台统一的（蒸汽模式只支持策略 2.0）。 如果你在网上看到"页面样式会影响组件""可以用 v-deep 穿透"的老说法，那是 5.0 之前的旧规则，别照抄。

3.2

ucss 能力边界与 CSS 变量

15 分钟 · 讲授

ucss 是 Web CSS 的子集，但它"缺的"比想象中少。下面这张表可以当作写样式时的地图： 左边这些能力都能用，右边那些别写。

类别可以放心用不要用
布局 display: flex（默认）、flex-direction、justify-content、align-items、flex-wrap、flex、gap 的替代 margin、绝对定位 position float、display: grid、gap / row-gap / column-gap
盒模型 width / height / min-width / max-height、padding / margin、border 系列、border-radius、box-sizing（默认 border-box） 依赖 content-box 的宽度计算习惯
文字 font-size / font-weight / font-family / font-style、color、line-height、letter-spacing、text-align、text-overflow、white-space、word-break、text-decoration、text-shadow CSS lines（已废弃，改用 text 的 :max-lines）、伪元素做装饰
视觉 background-color、box-shadow、opacity、overflow、visibility、z-index（同层兄弟间） 任意层级"盖住"别人、脱离节点树的层级控制
变换与动效 transform、transform-origin、transition 系列、animation 系列、@keyframes 用改变宽高/边距来做高频动画（性能差且易抖动）
选择器 单一 class（唯一推荐） 标签、#id、属性、通配符 *、伪类、伪元素
单位与函数 px（优先）、rpx、百分比；var()、env()、rgb() / rgba()、url() rem / em、inherit / unset
!
calc() 请谨慎：

官方 CSS 方法页把 calc() 列在支持清单里，但官方 position 文档的示例注释又写着 "App 端暂不支持 calc"——两处表述矛盾。 本章的写法都刻意避开 calc()；确实需要时请先在真机上验证，或改成"用 margin / padding 补足"。

CSS 变量：一个 class 定义，整棵子树使用

这是本章最有价值的一个技能。CSS 变量可以定义在 class 上，子元素通过 var() 使用 （官方暗黑模式示例正是这种写法），于是"设计令牌"就有了落地方式： 颜色、间距、圆角集中定义，页面里只引用变量名。

App.uvue —— 用 CSS 变量建立设计令牌 
<style>
  /* 令牌统一挂在 .page 上：页面根节点用这个 class，整棵子树都能用 var() 取值 */
  .page {
    /* 品牌色 */
    --brand: #2F6BFF;
    --brand-dark: #1E4FD8;
    --danger: #E5484D;
    /* 文字 */
    --text: #111C33;
    --text-sub: #5A6B8C;
    /* 背景与卡片 */
    --bg: #F5F8FF;
    --card: #FFFFFF;
    /* 间距（4 的倍数，保持节奏感） */
    --sp-1: 4px;
    --sp-2: 8px;
    --sp-3: 12px;
    --sp-4: 16px;
    --sp-5: 24px;
    /* 圆角与阴影 */
    --radius-sm: 8px;
    --radius: 12px;
    --radius-lg: 20px;
  }

  /* 通用工具类 */
  .card {
    background-color: var(--card);
    border-radius: var(--radius);
    padding: var(--sp-4);
  }
  .row { flex-direction: row; align-items: center; }
  .title { font-size: 17px; font-weight: bold; color: var(--text); }
  .muted { font-size: 13px; color: var(--text-sub); }
  .btn-primary { background-color: var(--brand); border-radius: var(--radius-sm); }
</style>
💡
为什么要这么做？

因为"改一处、全站生效"。想让全站主色从蓝改成绿，只改 --brand 一行； 想让间距整体放松 20%，只改 --sp-* 五个值。 反面教材是硬编码：一个项目里出现 17 种不同的灰色，是代码评审时最典型的"初级痕迹"。

3.3

质感三件套：圆角、阴影、图标

15 分钟 · 讲授 + 演练

移动端界面"高级感"的来源其实很朴素：一致的圆角、有层次的阴影、克制的图标。 这三样都不需要设计功底，只需要有意识地统一。

元素建议规范说明
圆角 大卡片 12–16px，小控件 8px，头像与按钮做全圆（半径 = 高度的一半） 圆角大小要成体系，别出现 6/7/9/13 这种随手写的值
阴影 只保留 2–3 个层级：卡片 0 2px 10px rgba(17,28,51,.06)，浮层 0 8px 24px rgba(17,28,51,.12)，弹窗 0 20px 50px rgba(17,28,51,.18) 阴影靠"低透明度 + 大模糊"显得轻，靠"高透明度 + 小模糊"显得硬。同一页面里别混用风格
图标 App 端不支持伪元素，字体图标用 unicode 直显：把图标字符写在 text 里，字体用 font-family 指定 更省事的方案是直接用 image 或 SVG；纯色小图标也可以用 unicode 符号（如 ★ ✓ ➜）
!
关于渐变：先验证再使用。

background-image 属性在官方清单中，但渐变（linear-gradient）在各端的支持程度并不完全一致， 官方也没有把它列为独立的 CSS 方法。所以课堂上的做法是： 能用纯色 + 阴影表达层次就别上渐变；一定要用渐变时，先在 Android 真机上确认效果再写进项目。 课程站演示里的渐变只是浏览器效果，不代表 App 端一定一致。

💡
一条能立刻提升观感的小技巧：

卡片不要用纯黑阴影，也不要给卡片加边框——两者叠加会显得"脏"。 浅色背景上，白色卡片 + 一层极淡的阴影就足够分层；深色模式下则相反，用略亮的卡片底色分层，不用阴影。

3.4

动效：transition 与 @keyframes

15 分钟 · 讲授 + 演练

动效只有两类用法，分清就不会乱： transition 负责"状态变化时的平滑过渡"（按下、展开、变色）； animation + @keyframes 负责"自己会动的循环动画"（加载、呼吸、提示）。

需求用哪个关键写法
按钮按下时轻微缩小transition默认态 transform: scale(1)；按下（hover-class）时 transform: scale(0.96)，并写 transition: transform .15s
颜色 / 透明度渐变transitiontransition: background-color .25s, opacity .25s
加载中旋转的圈animation@keyframes spin { from { transform: rotate(0deg) } to { transform: rotate(360deg) } } + animation: spin 1s linear infinite
呼吸 / 脉冲提示animation关键帧里只改 transform 与 opacity
ⓘ
动效的性能铁律：只动 transform 和 opacity。

因为这两个属性不需要重新计算布局。反过来，动画里去改 width / height / margin / top， 每一帧都要重新排版，低端机上必然掉帧。 另外 transition 与 animation 都支持简写，也都能拆成 transition-property / animation-duration 这类子属性——正式项目里写全子属性，可读性更好。

3.5

暗黑模式：官方推荐的媒体查询方案

20 分钟 · 讲授 + 交互演示

先建立概念：uni-app x 里有三种主题，别混着用。

主题概念是什么获取监听平台
osTheme 手机操作系统的主题 uni.getDeviceInfo().osTheme uni.onOsThemeChange() App
hostTheme 浏览器 / 小程序宿主的主题 uni.getAppBaseInfo().hostTheme uni.onHostThemeChange() Web / 小程序
appTheme 应用自己的主题（可以不跟随系统） uni.getAppBaseInfo().appTheme uni.onAppThemeChange() App

推荐方案：媒体查询 + CSS 变量（不需要监听、不需要切 class）

在 Web / 小程序平台，以及 HBuilderX 5.25+ 的 App 蒸汽模式下， 可以直接用 @media (prefers-color-scheme: light) 与 (prefers-color-scheme: dark) 写两套变量值。 主题变化时样式会自动匹配，既不消耗性能，也不会闪烁。

页面里适配主题（推荐写法） 
<style>
  /* 亮色：只改变量值，不重复写结构样式 */
  @media (prefers-color-scheme: light) {
    .page {
      --bg: #F5F8FF;
      --card: #FFFFFF;
      --text: #111C33;
      --text-sub: #5A6B8C;
    }
  }

  /* 暗色 */
  @media (prefers-color-scheme: dark) {
    .page {
      --bg: #0E1626;
      --card: #182238;
      --text: #E6EDF9;
      --text-sub: #93A4C4;
    }
  }

  /* 结构样式只写一份，颜色全部走变量 */
  .page { flex: 1; padding: 16px; background-color: var(--bg); }
  .card { background-color: var(--card); border-radius: 12px; padding: 16px; }
  .title { font-size: 16px; font-weight: bold; color: var(--text); margin-bottom: 6px; }
  .muted { font-size: 13px; color: var(--text-sub); }
</style>

两个高频误区：

① theme.json 里的变量只能用于 pages.json，页面（uvue）里引用不到。 页面的颜色要在页面的样式里用 CSS 变量方案自己管理； ② uni.setAppTheme() 是 App 平台的 API（Android / iOS 4.18+，鸿蒙 4.71+）， Web 与小程序不支持——所以在浏览器里点"切换主题"没反应是正常的，它跟随的是浏览器/宿主主题。

ⓘ
老平台的兼容方案（了解即可）：

在 HBuilderX 5.25 之前的 App、以及 App 的 VDOM 模式下不支持媒体查询， 只能用"监听主题变化 + 动态切换 class"：在 App.uvue 里监听 uni.onOsThemeChange / uni.onAppThemeChange，把结果存进全局响应式状态， 页面根节点写成 :class="state.isDark ? 'theme-dark' : 'theme-light'"， 再在全局样式里定义 .theme-light / .theme-dark 两套变量。 官方明确指出这个方案性能不如媒体查询，而且与 theme.json 不在同一帧生效时会闪烁， 所以能用媒体查询就用媒体查询。

3.6

样式组织：一个项目该有几种样式文件

10 分钟 · 讲授

样式隔离讲清楚之后，组织方式就顺理成章了。推荐按"令牌 → 工具类 → 页面/组件样式"三层来放：

层放什么写在哪谁能用
第一层 · 令牌 颜色、间距、圆角、字号变量，以及亮/暗两套取值 App.uvue 的 <style>（挂在 .page 上） 所有页面（页面的默认策略是 app）；组件需要显式声明才可用
第二层 · 工具类 .card .row .title .muted .btn-primary 这类跨页面复用的 class 同上，App.uvue 里 同上
第三层 · 页面与组件私有样式 只服务于当前页面/组件的布局与细节 各自 .uvue 的 <style> 自身（组件默认隔离，需 app / app-and-page 才引用全局）
💡
三个实操建议：

① 全局只放"确定性"的东西（令牌与工具类），别把某个页面的特殊布局塞进全局； ② 组件样式自带，需要外部定制的部分用 externalClasses 开口子，不要指望外部覆盖内部 class； ③ 全项目统一命名规范（例如令牌用 -- 前缀、工具类用语义名 .card、页面局部用 .页面名-元素）， 这样一年后回来看代码还能看懂。

✓
判断一个项目的样式是否"健康"，看三个信号：

① 搜索颜色值（如 #5A6B8C）只在令牌定义处出现； ② 同一个元素的样式不会被三处地方同时定义； ③ 删掉一个组件文件，页面其他部分不受影响。三条都满足，说明隔离与令牌都用对了。

📌 今天你学到的，浓缩成 6 句话

class 有三个来源：全局（App.uvue）、页面、组件； 组件默认 isolated、页面默认 app，所以组件里用不到全局 class，需要 defineOptions 显式放开； 组件对外定制样式的正规做法是 externalClasses + 传入 class 名； CSS 变量定义在 class 上、子元素用 var() 引用，这就是全站设计令牌的落地方式； 动效只动 transform 与 opacity，transition 管状态过渡、animation 管循环动画； 暗黑模式优先用 @media (prefers-color-scheme) + CSS 变量（App 需 5.25+ 蒸汽模式）， 导航栏与 tabBar 的亮暗配色交给 theme.json，运行时切换用 uni.setAppTheme。
