5.1

事件绑定：方法引用、内联传参、长按

15 分钟 · 讲授

uni-app x 的事件绑定统一用 @事件名。移动端最常用的四个事件是 点击 @click、长按 @longpress、 输入 @input（表单组件）、值变化 @change（开关 / 滑块 / 选择器）。

写法用法什么时候用
@click="onTap" 方法引用：直接写函数名，不加括号 最常用，函数不需要外部参数时一律用这种
@click="remove(item.id)" 内联调用：在模板里直接传参 列表里"删这一条""打开这一条"这类需要行内数据的场景
@longpress="onLongPress" 长按触发 移动端高频交互：长按复制、长按删除、长按多选
pages/demo/event.uvue —— 三种事件写法 
<template>
  <view class="page">
    <!-- ① 方法引用：不加括号 -->
    <button @click="addOne">新增一条</button>

    <!-- ② 内联传参：把行内数据带给函数 -->
    <view v-for="item in list" :key="item.id" class="item">
      <text class="item-text">{{ item.title }}</text>
      <text class="del" @click="remove(item.id)">删除</text>
    </view>

    <!-- ③ 长按：移动端特有的交互方式 -->
    <view class="item" hover-class="pressed" @longpress="copyAll">
      <text class="item-text">长按复制全部标题</text>
    </view>
  </view>
</template>

<script setup>
  type Notice = { id: number, title: string }

  const list = ref<Notice[]>([
    { 'id': 1, 'title': '数据结构作业' },
    { 'id': 2, 'title': '社团例会' }
  ])

  const addOne = () => {
    const nextId = list.value.length + 1
    // 整体赋值，最可靠
    list.value = list.value.concat({ 'id': nextId, 'title': '新通知 ' + nextId })
  }

  const remove = (id: number) => {
    list.value = list.value.filter((item) => item.id != id)
  }

  const copyAll = () => {
    const text = list.value.map((item) => item.title).join('、')
    uni.setClipboardData({ 'data': text })          // 复制到剪贴板
    uni.showToast({ 'title': '已复制', 'icon': 'none' })
  }
</script>
💡
两条经验：

① 能用方法引用就别用内联调用——内联写法在循环里会为每一项生成一个新函数，列表长时有额外开销； ② 移动端没有鼠标悬停，点击反馈靠 hover-class（第 3 章讲过，它的默认值是 none，必须显式指定）。

5.2

输入框：input 与 textarea 的体验细节

30 分钟 · 讲授 + 演练

输入框是表单里最需要"抠细节"的组件。同一段文字，键盘类型选错，用户就要多切换两次输入法—— 这是移动端体验里最容易被用户感知、也最容易改好的地方。

先解决一个关键问题：双向绑定怎么写

✕
官方 input 属性表里没有 v-model。

官方给出的写法是 :value 绑定数据 + @input 接收输入： <input :value="keyword" @input="onInput" />。 v-model 出现在 Vue 的「内置指令」清单里，属于语法糖；但组件属性表中并未列出它， 所以本课程统一使用 :value + @input： 写法明确、各端行为一致、出错时也更容易定位。 如果确实想用 v-model，请先在真机上验证再写进项目。

pages/demo/input.uvue —— 官方写法的双向绑定 
<template>
  <view class="page">
    <!-- :value 显示数据；@input 接收用户输入并写回数据 -->
    <input
      class="field"
      :value="keyword"
      placeholder="搜索课程"
      placeholder-class="ph"
      confirm-type="search"
      @input="onInput"
      @confirm="onConfirm" />

    <text class="muted">输入内容：{{ keyword }}（{{ keyword.length }} 个字）</text>
  </view>
</template>

<script setup>
  const keyword = ref<string>('')

  // 事件对象里带着当前输入值：event.detail = { value, cursor }
  const onInput = (event: UniInputEvent) => {
    keyword.value = event.detail.value
  }

  const onConfirm = () => {
    // 用户按下键盘右下角的"搜索"时触发
    uni.showToast({ 'title': '搜索：' + keyword.value, 'icon': 'none' })
  }
</script>

<style>
  .page { flex: 1; padding: 16px; background-color: #FFFFFF; }
  .field { height: 44px; background-color: #F5F8FF; border-radius: 10px; padding-left: 12px; padding-right: 12px; }
  .ph { color: #A8B0BF; font-size: 14px; }
  .muted { font-size: 13px; color: #5A6B8C; margin-top: 10px; }
</style>
✓
一个非常好用、但很多人不知道的特性：

@input 的处理函数可以直接 return 一个字符串来替换输入框内容。 于是"只允许输入数字""自动转大写""去掉空格"这类需求，不用再手动改数据，一行 return 就够：

输入过滤：手机号只允许数字 
<script setup>
  const phone = ref<string>('')

  // return 出去的字符串会直接替换输入框里的内容
  const onPhoneInput = (event: UniInputEvent): string => {
    const cleaned = event.detail.value.replace(/[^0-9]/g, '')   // 只保留数字
    phone.value = cleaned
    return cleaned
  }

  // 需要"受控"时，再给 input 加 controlled 属性：
  // value 将完全由数据决定，避免出现"数据与输入框不一致"
</script>

<template>
  <input
    class="field"
    type="number"
    maxlength="11"
    :value="phone"
    controlled
    placeholder="请输入手机号"
    @input="onPhoneInput" />
</template>

input 的属性速查

属性作用怎么用
type决定弹出哪种虚拟键盘取值：text（默认）/ number / digit（带小数点）/ idcard / tel / email / url / safe-password / nickname / none（不弹键盘）
password密码类型（显示为圆点）布尔属性，配合 type="text" 或 safe-password 使用
confirm-type键盘右下角按钮上的文字取值 send / search / next / go / done（默认 done），仅在 type="text" 时生效
maxlength最大输入长度默认 -1 表示不限制；手机号写 11、验证码写 6
placeholder / placeholder-class占位文字与它的样式占位文字样式要单独用一个 class（样式不继承）
adjust-position键盘弹起时是否自动上推页面默认 true；表单在页面底部被键盘挡住时优先检查它
cursor-spacing / cursor-color光标与键盘的距离 / 光标颜色输入框贴屏幕底部时给 cursor-spacing 一点余量
auto-focus / focus自动聚焦auto-focus 只在首次生效；需要反复控制焦点用 focus
disabled禁用注意：在 form 里 被禁用的表单项仍然会被提交（见 5.6）

textarea：多行输入的三个专属属性

属性 / 事件作用注意
auto-height高度随内容自动增长开启后 style 里的 height 不生效——写留言框、评论框最常用
show-confirm-bar是否显示键盘上方的"完成"栏iOS 上默认显示，写长文本时可关掉争取空间
adjust-keyboard-to键盘弹出时的对齐方式取值 cursor（对齐光标，默认）/ bottom（对齐底部）
@linechange行数变化时触发（可拿到高度）做"展开全文"这类效果时有用
无 type / password—多行输入不需要键盘类型，所以这两个属性不存在
!
input 与 textarea 的一个行为差异：

input 的 @input 处理函数 可以 return 字符串替换内容； 而 textarea 的 @input 返回值不生效。 所以在 textarea 上做输入过滤时，必须老老实实"先清洗数据、再赋回去"。

5.3

开关与滑块：switch / slider

15 分钟 · 讲授 + 演练
组件关键属性事件返回值
switch checked、disabled、foreColor（滑块颜色）、activeForeColor、backgroundColor、activeBackgroundColor、thumb-class / thumb-active-class / switch-active-class、type @change → event.detail.value 是 boolean
slider min / max / step、value、disabled、show-value、block-size、activeBackgroundColor / backgroundColor、foreColor、track-class / track-active-class / thumb-class @change（拖动结束）→ number；@changing（拖动中）→ number
✕
三个已经废弃的属性名（老教程里很常见）：

switch 的 color → 改用 foreColor； slider 的 activeColor / block-color / color / selected-color → 改用 activeBackgroundColor / thumb-class / foreColor / track-active-class。 官方还特别注明：蒸汽模式下 slider 的颜色请用 track-class / thumb-class 这类 class 来定制。

pages/demo/switch-slider.uvue 
<template>
  <view class="page">
    <view class="row">
      <text class="label">接收通知</text>
      <!-- 开关：值来自数据，变化后写回数据 -->
      <switch :checked="notifyOn" foreColor="#2F6BFF" @change="onNotifyChange" />
    </view>

    <view class="row">
      <text class="label">每天学习时长（{{ hours }} 小时）</text>
    </view>
    <!-- 滑块：step 必须能整除 max - min -->
    <slider :value="hours" :min="0" :max="8" :step="1" show-value @change="onHoursChange" />
  </view>
</template>

<script setup>
  const notifyOn = ref<boolean>(true)
  const hours = ref<number>(2)

  const onNotifyChange = (event: UniSwitchChangeEvent) => {
    notifyOn.value = event.detail.value          // boolean
  }

  const onHoursChange = (event: UniSliderChangeEvent) => {
    hours.value = event.detail.value             // number
  }
</script>

<style>
  .page { flex: 1; padding: 16px; background-color: #FFFFFF; }
  .row { flex-direction: row; justify-content: space-between; align-items: center; height: 48px; }
  .label { font-size: 15px; color: #111C33; }
</style>
💡
两条实践提醒：

① slider 的 step 必须大于 0 且能整除 max - min， 否则在部分平台"拖不到最右端"（官方说明：该问题在 iOS 4.33 起已一致，Android / Web 需自己注意）； ② iOS 端的 switch / slider 不支持 padding， 要靠 margin 做位置微调，否则会出现双端间距不一致。

5.4

多选与单选：checkbox-group / radio-group

15 分钟 · 讲授

移动端做"选一个"和"选多个"，规范做法是用组组件包住单项组件： radio-group 包 radio、checkbox-group 包 checkbox。 变化事件绑在组上，而不是单项上——这是最容易写错的地方。

组件写法要点@change 的返回值
radio-group
+ radio		 事件绑在 radio-group 上；每个 radio 用 value 标识自己，用 checked 控制选中 event.detail.value 是被选中项的 string
checkbox-group
+ checkbox		 同样绑在组上；支持一次选中多个，通常配合"最多选 3 个"这类限制逻辑 event.detail.value 是选中项的 string 数组
pages/demo/choice.uvue —— 单选 + 多选（带选择上限） 
<template>
  <view class="page">
    <!-- 单选：事件绑在 radio-group 上 -->
    <text class="section-title">选择年级</text>
    <radio-group @change="onGradeChange">
      <label class="opt" v-for="g in grades" :key="g">
        <radio :value="g" :checked="grade == g" color="#2F6BFF" />
        <text class="opt-text">{{ g }}</text>
      </label>
    </radio-group>

    <!-- 多选：事件同样绑在 group 上，返回值是数组 -->
    <text class="section-title">选择感兴趣的社团（最多 2 个）</text>
    <checkbox-group @change="onClubChange">
      <label class="opt" v-for="c in clubs" :key="c">
        <checkbox :value="c" :checked="pickedClubs.indexOf(c) >= 0" />
        <text class="opt-text">{{ c }}</text>
      </label>
    </checkbox-group>

    <text class="muted">已选：{{ pickedClubs.join('、') }}</text>
  </view>
</template>

<script setup>
  const grades = ref<string[]>(['大一', '大二', '大三', '大四'])
  const clubs = ref<string[]>(['编程社', '摄影社', '篮球队', '志愿者协会'])

  const grade = ref<string>('')
  const pickedClubs = ref<string[]>([])

  const onGradeChange = (event: UniRadioGroupChangeEvent) => {
    grade.value = event.detail.value                    // string
  }

  const onClubChange = (event: UniCheckboxGroupChangeEvent) => {
    const picked = event.detail.value                   // string[]
    if (picked.length > 2) {
      uni.showToast({ 'title': '最多选 2 个', 'icon': 'none' })
      // 通过"不改数据"来拒绝这次修改，界面会回到原状态
      return
    }
    pickedClubs.value = picked
  }
</script>

<style>
  .page { flex: 1; padding: 16px; background-color: #FFFFFF; }
  .section-title { font-size: 15px; font-weight: bold; margin-top: 18px; margin-bottom: 6px; }
  .opt { flex-direction: row; align-items: center; height: 44px; }
  .opt-text { font-size: 14px; color: #111C33; margin-left: 8px; }
  .muted { font-size: 13px; color: #5A6B8C; margin-top: 10px; }
</style>
!
两个跨端注意点：

① checkbox / radio 的颜色属性 color / iconColor 已废弃， 现在用 foreColor、backgroundColor、borderColor、activeBackgroundColor、activeBorderColor 等， 或直接用 icon-class / checkbox-class / radio-class 定制； ② 在支付宝小程序里，checkbox / radio 不能内嵌 text， 文字要像上面的例子那样写在 label 里的同级位置。

5.5

picker：底部弹出的滚动选择器

20 分钟 · 讲授 + 演练

在手机上"选一个值"的最优解不是下拉框，而是从底部弹出一列滚动选择—— 这就是 picker。它用一个 mode 属性切换五种模式：

mode用途常用属性@change 返回
selector（默认）从一维数组里选一项range、value（下标）、range-key（对象数组时指定显示字段）下标（number）
multiSelector多列联动选择（如"学院 + 专业"）range 是二维数组、@columnchange 处理列变化下标数组
time选时间value、start、end时间字符串
date选日期value、start、end、fields（year/month/day）日期字符串
region省市区三级联动value、level（province/city/region/sub-district）地名数组
pages/demo/picker.uvue —— 课程选择 + 日期选择 
<template>
  <view class="page">
    <!-- ① selector：从数组里选一项；range-key 用于对象数组 -->
    <picker mode="selector" :range="courses" range-key="name" :value="courseIndex" @change="onCourseChange">
      <view class="field">
        <text class="field-text">{{ courseIndex >= 0 ? courses[courseIndex].name : '请选择课程' }}</text>
        <text class="arrow">›</text>
      </view>
    </picker>

    <!-- ② date：选日期，fields 控制精度 -->
    <picker mode="date" :value="date" :start="'2026-01-01'" :end="'2026-12-31'" fields="day" @change="onDateChange">
      <view class="field">
        <text class="field-text">{{ date.length > 0 ? date : '请选择日期' }}</text>
        <text class="arrow">›</text>
      </view>
    </picker>
  </view>
</template>

<script setup>
  type Course = { 'name': string }

  const courses = ref<Course[]>([
    { 'name': '移动应用开发' },
    { 'name': '数据结构' },
    { 'name': '计算机网络' }
  ])

  const courseIndex = ref<number>(-1)
  const date = ref<string>('')

  const onCourseChange = (event: UniPickerChangeEvent) => {
    // selector 模式返回的是下标（number）
    courseIndex.value = event.detail.value as number
  }

  const onDateChange = (event: UniPickerChangeEvent) => {
    // date 模式返回的是字符串；注意不同平台的分隔符可能不同（见下方提示）
    date.value = event.detail.value as string
  }
</script>

<style>
  .page { flex: 1; padding: 16px; background-color: #FFFFFF; }
  .field {
    height: 48px; flex-direction: row; align-items: center; justify-content: space-between;
    border-bottom: 1px solid #E2E9F7;
  }
  .field-text { font-size: 15px; color: #111C33; }
  .arrow { font-size: 18px; color: #A8B0BF; }
</style>
✕
三个必须知道的坑：

① 日期返回值在不同平台格式不同：官方注明支付宝小程序的日期 change 返回 "2026/10/11"， 而微信返回 "2026-10-11"。要存库或比较大小，请先统一格式再处理； ② picker 在 Android / iOS 需要 HBuilderX 5.08+；更低版本请改用 picker-view 或 uni.showActionSheet； ③ picker 本身不显示内容，你必须自己在里面放一个 view 当"触发器"—— 所以它的样式要按普通 view 来设计。

5.6

表单提交与校验：form 组件与手写校验两条路

20 分钟 · 讲授

官方提供了 form 组件，用 name 收集字段、用 @submit 一次性拿到所有值。 但它有明确的适用边界，先看清楚规则再决定用哪条路。

规则官方说明对你的影响
能放进 form 的表单项 只支持 input / textarea / checkbox / radio / switch / slider，配合 button 的 form-type 不支持把自定义组件当表单项——封装了输入控件就要自己收集数据
@submit 的返回值 event.detail.value 是一个对象，键是各表单项的 name 取值时用 value['phone'] 这样的方式读
同名字段 同名 name 只保留最后一个 不要给不同字段起相同的 name
被禁用的表单项 仍然会被提交 想让字段"不提交"，就不要放进 form，或者自己收集数据
重置 @reset（App 3.97+ / Web 4.0+ 起为"还原"） 重置会还原到初始值，不只是清空
ⓘ
怎么选：

纯原生控件、字段简单（比如"姓名 + 留言"）→ 用 form + name + @submit，省事； 需要即时校验、联动、或者用了自定义组件 → 用 ref 自己收集数据 + 自己校验。 真实项目里第二种更常见，因为"什么时候允许提交"本身就是一类派生数据，正好用得上第 4 章的 computed。

两条路的代码对照 
<template>
  <form @submit="onSubmit">
    <input name="username" placeholder="姓名" />
    <input name="phone" type="number" placeholder="手机号" />
    <switch name="agree" />
    <button form-type="submit" type="primary">提交</button>
    <button form-type="reset">重置</button>
  </form>
</template>

<script setup>
  const onSubmit = (event: UniFormSubmitEvent) => {
    // detail.value 是一个对象：{ username: '...', phone: '...', agree: true }
    const form = event.detail.value
    console.log('name =', form['username'])
    console.log('phone =', form['phone'])
  }
</script>
<script setup>
  const name = ref<string>('')
  const phone = ref<string>('')

  // 错误信息也由数据推导：没填过就不报错（避免一进页面满屏红字）
  const nameError = computed(() => {
    if (name.value.length == 0) return ''
    return name.value.length < 2 ? '姓名至少 2 个字' : ''
  })

  const phoneError = computed(() => {
    if (phone.value.length == 0) return ''
    return phone.value.length == 11 ? '' : '手机号应为 11 位'
  })

  // 只有全部合法才允许提交
  const canSubmit = computed(() => {
    return name.value.length >= 2 && phone.value.length == 11
  })

  const submitting = ref(false)

  const submit = () => {
    if (!canSubmit.value || submitting.value) return   // 双保险：防重复提交
    submitting.value = true
    setTimeout(() => {
      submitting.value = false
      uni.showToast({ 'title': '提交成功', 'icon': 'none' })
    }, 600)
  }
</script>
!
上线前必做的三件事：

① 校验：必填、长度、格式（手机号、邮箱）至少各有一条； ② 禁用提交按钮：canSubmit 为 false 时给按钮加 disabled，不要让用户点了才被告知不合格； ③ 防重复提交：提交期间把 submitting 置为 true 并挡住再次点击—— 没有这一步的表单，在网络慢的时候会产生重复订单，是最常见的线上事故之一。

5.7

实战：一个可上线的"活动报名表"

30 分钟 · 全程动手

把本章所有组件拼起来，做一个真实场景：社团活动报名。 需求：姓名（输入）、手机号（数字键盘 + 只允许数字 + 11 位）、年级（底部选择器）、 参加人数（滑块 1–5）、同意须知（开关），校验通过才允许提交，提交中禁止重复点击。

pages/signup/signup.uvue 
<template>
  <view class="page">
    <!-- 姓名 -->
    <view class="form-item">
      <text class="label">姓名</text>
      <input class="field" :value="name" placeholder="请输入真实姓名" @input="onNameInput" />
    </view>
    <text v-if="nameError.length > 0" class="error">{{ nameError }}</text>

    <!-- 手机号：数字键盘 + 输入过滤 + 长度限制 -->
    <view class="form-item">
      <text class="label">手机号</text>
      <input class="field" type="number" maxlength="11" :value="phone"
             placeholder="11 位手机号" @input="onPhoneInput" />
    </view>
    <text v-if="phoneError.length > 0" class="error">{{ phoneError }}</text>

    <!-- 年级：底部选择器 -->
    <view class="form-item">
      <text class="label">年级</text>
      <picker mode="selector" :range="grades" :value="gradeIndex" @change="onGradeChange">
        <view class="field picker-field">
          <text :class="gradeIndex >= 0 ? 'field-text' : 'field-text placeholder-text'">
            {{ gradeIndex >= 0 ? grades[gradeIndex] : '请选择' }}
          </text>
        </view>
      </picker>
    </view>

    <!-- 参加人数：滑块 -->
    <view class="form-item column">
      <text class="label">参加人数：{{ people }} 人</text>
      <slider :value="people" :min="1" :max="5" :step="1" activeBackgroundColor="#2F6BFF"
              @change="onPeopleChange" />
    </view>

    <!-- 同意须知：开关 -->
    <view class="form-item">
      <text class="label">我已阅读并同意活动须知</text>
      <switch :checked="agreed" foreColor="#2F6BFF" @change="onAgreeChange" />
    </view>

    <!-- 提交：禁用态 + 加载态 + 防重复 -->
    <button class="submit" type="primary" :disabled="!canSubmit || submitting"
            :loading="submitting" @click="submit">
      {{ submitting ? '提交中…' : '提交报名' }}
    </button>
    <text class="muted">{{ canSubmit ? '信息已填完整，可以提交' : '请先补全信息' }}</text>
  </view>
</template>
<script setup>
  const grades = ref<string[]>(['大一', '大二', '大三', '大四'])

  const name = ref<string>('')
  const phone = ref<string>('')
  const gradeIndex = ref<number>(-1)
  const people = ref<number>(1)
  const agreed = ref<boolean>(false)

  const submitting = ref(false)

  /* ---------- 输入处理：input 的 @input 可以直接 return 清洗后的内容 ---------- */
  const onNameInput = (event: UniInputEvent) => {
    name.value = event.detail.value
  }

  const onPhoneInput = (event: UniInputEvent): string => {
    const cleaned = event.detail.value.replace(/[^0-9]/g, '')
    phone.value = cleaned
    return cleaned
  }

  const onGradeChange = (event: UniPickerChangeEvent) => {
    gradeIndex.value = event.detail.value as number
  }

  const onPeopleChange = (event: UniSliderChangeEvent) => {
    people.value = event.detail.value
  }

  const onAgreeChange = (event: UniSwitchChangeEvent) => {
    agreed.value = event.detail.value
  }

  /* ---------- 校验：全部用 computed 推导，不手动维护 ---------- */
  const nameError = computed(() => {
    if (name.value.length == 0) return ''
    return name.value.length < 2 ? '姓名至少 2 个字' : ''
  })

  const phoneError = computed(() => {
    if (phone.value.length == 0) return ''
    return phone.value.length == 11 ? '' : '手机号应为 11 位数字'
  })

  const canSubmit = computed(() => {
    return name.value.length >= 2
      && phone.value.length == 11
      && gradeIndex.value >= 0
      && agreed.value
  })

  /* ---------- 提交 ---------- */
  const submit = () => {
    if (!canSubmit.value || submitting.value) return
    submitting.value = true

    // 真实项目里这里是 uni.request（第 8 章）
    setTimeout(() => {
      submitting.value = false
      uni.showModal({
        'title': '报名成功',
        'content': name.value + '，' + grades.value[gradeIndex.value] + '，' + people.value + ' 人',
        'showCancel': false
      })
    }, 800)
  }
</script>

  }

  .field { flex: 1; height: 44px; margin-left: 12px; font-size: 15px; text-align: right; }

💡
这段代码里值得记住的四个模式：

① 数据只存"源状态"（姓名、手机号、下标、人数、开关），错误信息与"能否提交"全部由 computed 推导； ② 错误提示只在用户开始输入之后才显示（没填过就不报错），避免一进页面满屏红字； ③ 输入过滤用 @input 的 return 值，比事后在提交时清洗体验更好； ④ 提交按钮同时受 disabled 与 submitting 控制，这是防重复提交的标准做法。

📌 今天你学到的，浓缩成 6 句话

事件用 @事件名：方法引用不加括号，需要行内数据时用 @click="fn(item)"，长按用 @longpress； 输入框官方写法是 :value + @input（v-model 未出现在官方属性表中）， @input 可以直接 return 字符串替换内容，这是做输入过滤最优雅的方式； 选对 type（键盘类型）与 confirm-type（回车键文字）能明显提升输入体验， type 里的 number / digit / tel 各有用途； 开关、滑块、单选、多选、选择器的变化事件统一是 @change， 值分别落在 detail.value 的 boolean / number / string / string[] 上，取值类型必须分清； form 组件能一次性收表，但不支持自定义组件当表单项、禁用的字段也会被提交； 真实项目建议自己收集 + computed 校验，并做到校验、禁用提交、防重复提交三件事。

@click / @longpress 方法引用 vs 内联传参 :value + @input @input return 过滤 type 键盘类型 confirm-type controlled 受控 textarea auto-height switch @change boolean slider step radio-group 单选 checkbox-group 多选 picker 五种 mode form + name computed 校验 防重复提交
